## 3. 施工模块与验收顺序

按01的D21次序实施，避免先跑投资曲线再补账本：

1. **公共输入与事实：**Schema校验、身份/单位/时间、数据来源与历史事实选择。
2. **股数现金账户：**唯一账本、公司行动、资本流、精确份额、税费、幂等与断点恢复。先跑固定事件链。
3. **策略决策：**400池、因子包、百分位、30/45缓冲、固定目标金额和FLAT_SCORE边界。

6. **人工前向：**仅在真实能力另经核验后按受限范围生成清单、导入回报和对账，不启用自动报撤单。

# 小市值周频选股策略
## 概要设计 V5｜详细设计基线

**版本日期：2026年10月16日**  
**用途：确定策略规则、职责边界、验证方法和采用条件，直接指导详细设计。**

本版在V4基础上修订，纳入QMT优先、证券范围完全不重叠、共享现金人工串行协调，以及运行持续性准入。V4保留，不再作为本轮详细设计主文。正文规定采用的方案；评审理由和算例另见《V5评审处理与详细设计边界》。

**设计基线已经明确，不代表投资效果、外部数据或账户能力已经验证。** 最终因子包、实际资金与权限、券商清算配置及外部能力验收集中列在第15节。除此之外，详细设计按本文展开，不自行改动规则以改善历史成绩。本版不开发生产代码，不授权真实交易，也不要求重构ETF系统。

## 1. 投资定位与确定的业务前提

### 1.1 投资目标

本策略投资沪深非金融普通A股，现货做多、不融资、不做空。先形成小市值经济候选池，再以少数固定因子排序，持有约30只股票。常规选股和调仓按周进行，风险和账务每日检查。

总资金约50万—100万元，由ETF策略与本策略共享；本策略实际划拨金额待定，最高约50万元。收益和回撤只依据**真实归属本策略的全部净资产**计算，包括确实保留给本策略的现金，不包括ETF资产、未分配额度或已经转出的资金。

本策略独立承担约30%的回撤容忍度。采用评价要求各规定情景的连续净值最大回撤不超过30%；25%应急停用另构成运行持续性否决条件。发出退出指令不等于完成退出，也不保证未来回撤封顶。

### 1.2 证券范围完全不重叠

同时运行的只有ETF策略与一条个股策略，不运行第二条个股策略。两者证券范围完全互斥，由用户限制，证券及其成交、分红和税务记录按范围唯一归属。

本版不设计同一证券在多个策略之间的持仓分摊、同股成交争议、跨策略税务批次竞争、净额撮合或内部虚拟交易。证券归属与现金可用性分别管理；互斥范围不能替代共享现金核对。

### 1.3 核心规则总览

| 项目 | 本版确定的规则 |
|---|---|
| 数据优先级 | 同口径且合格的数据QMT优先，QMT不具备的由Tushare补充；维护期允许标识清楚的Tushare临时研究 |
| 经济候选池 | 共同资格过滤后按真实总市值取最小的最多400只；不读取评分因子 |
| 因子包 | 少量、固定、可替换；全部所需项有效后，平均并列百分位、方向统一、包内等权 |
| 中性化 | 主评分不做市值或行业中性化；研究报告必须展示相关暴露 |
| 名单 | 目标30只，合格老持仓排名不超过45时优先保留 |
| 仓位 | 股票目标60%，正常单股中心2%，普通偏离带1.5%—2.5% |
| 风险 | 单股5%、行业20%、总暴露超过65%向60%纠偏；20%回撤预警、25%应急退出 |
| 正常执行 | 周度信号后首个交易日10:00—10:30，先卖后买；每日风险使用之后首个允许窗口 |
| 共享现金 | 人工统一资金台账、串行交易批次、真实占用和对账；不假设已有完整协调模块 |
| 停用与采用 | 任一规定起点或压力回放触发真实25%应急停用，该候选配置不进入当前采用名单 |
| 实现路线 | 独立股票决策核心、小型事件回放、唯一股数现金路径；有限复用已核验工具 |

60%等数值是固定研究基线，不是收益优化结果或安全证明。首版不加入月份空仓、均线择时、自动恢复、机器学习调权和复杂组合优化；保留现金不自动投资其他资产。

## 2. 总体流程与责任边界

### 2.1 闭合运行链

> 统一来源与历史可用事实 → 经济400池 → 因子联合有效集与评分 → 基于实际持仓形成周度意图 → 风险与资金统一裁决 → 人工串行授权执行 → 成交和公司行动更新账本 → 下一次决策

普通计划、独立风险与账户约束在同一个裁决点合并。执行只落实已确定的意图，不临时换入其他股票。成交失败、部分成交、资本转移和冻结情况必须反馈到下一次决策。

### 2.2 必要职责

| 责任 | 负责什么 | 不负责什么 |
|---|---|---|
| 数据与时点 | 来源优先级、身份与单位统一、可用时间、版本、事件及缺口 | 不按历史收益挑来源，不替模型选择好公司 |
| 候选池与评分 | 经济资格、400池、因子联合覆盖、百分位和排名 | 不使用其他策略资金，不假定订单已成交 |
| 组合决策 | 保留、退出、补位、普通目标金额及调权 | 不越过现金、风险、名额和执行限制 |
| 风险与资金裁决 | 合并风险目标、预算和真实状态，形成唯一最终意图 | 不用未来回款或另一策略权益通过检查 |
| 执行反馈 | 数量、价格保护、期限、部分成交、撤单及终态 | 不重新选股，不把意图到期当作订单结束 |
| 账户与评价 | 股数现金、公司行动、净值、运行状态、压力和采用资格 | 不维护另一条可择优使用的正式净值 |
| 人工共享现金协调 | 双方资金划归、承诺占用、批次串行、转资及汇总对账 | 不分摊同股数量，不建设通用多策略交易平台 |

这些是逻辑责任，可以在单机脚本和本地文件中实现，不对应多个服务。历史回放、前向观察和实际运行采用同一经济规则；账户事实分别来自模拟执行或真实回报，不能混用。

## 3. 数据来源、历史时点与冲突处理

### 3.1 固定主次关系

**QMT和Tushare都提供的同口径、合格数据，以QMT为准；QMT没有的，由Tushare补充。** Tushare同时用于交叉检查。该规则同时适用于历史研究和日常运行，不再按“历史归Tushare、部署归QMT”划分。

“同口径”至少包括：同一证券及市场、同一日期或时点、同一单位、同一财务合并及期间口径、同一价格调整定义和股份基础。同名字段不自动视为同口径。QMT的当前总股本、当前行业或最新财报，不能替代历史时点数据；只有实际具备所需历史语义才构成优先来源。

| 数据情况 | 采用规则 |
|---|---|
| 双方同口径且均有效 | 使用QMT；Tushare保留作检查，不平均、不择优 |
| QMT未提供所需字段、日期或历史语义 | 使用已通过检查的Tushare补充，并保留实际来源 |
| QMT缺失、过期或明显错误 | 不使用该错误值；有已核验、同口径的Tushare数据时显式替代，否则记未知 |
| 仅为可解释的舍入或展示差异 | 统一精度后按QMT取值；不为无决策影响的差异启动全量重跑 |
| 实质冲突尚无法判断真伪 | 标记待核查，停止依赖该事实的新增风险；不得自动挑选对收益有利的一方 |
| 券商现金、持仓、委托、成交与实扣费用 | 只以券商确认记录及其QMT输出核对；Tushare不能补造账户事实 |

QMT优先是用户规定的来源政策，不是“QMT永远正确”的结论。法定交易规则和公司行动条款仍按有依据的生效事实校核；确认数据错误时纠正，不为维持来源优先级保留错误。

### 3.2 替代与跨源一致性

替代必须记录数据种类、证券／日期范围、实际来源、原因和可用时间。同一运行按事前确定的来源规则取数，不逐日或逐股按回测效果选择。

价格、复权因子、股份变化与公司行动须形成一致的计量基础。不得直接连接两个不同复权锚点的价序列；不得用一个来源的复权收益隐含再投资，再在账本重复入账现金分红。不同来源的原始财报输入只有在合并范围、期间、版本与可用时间可对齐时才可共同计算衍生指标。

来源、版本或单位不清的事实，按影响范围限制行动；个别未知不能删除真实持仓，全局事实不可信也不能批量虚构正常值。

### 3.3 QMT维护期及恢复后的处理

维护期使用Tushare推进数据核查、因子与日线代理研究，运行注明“临时Tushare来源”。这种研究可指导详细设计，但不等于已完成QMT主源验收或盘中执行验证。

QMT恢复后，核对实际使用的字段、历史区间及影响候选池、分数、交易、净值和采用结论的差异。无关字段、未使用区间和纯展示差异不要求重复全部工作。

**有决策或账务影响时，从最早受影响的决策或账户事件开始，重放该候选受影响的后续连续路径及相关起点／情景。** 不能只修出错当天而保留随后受影响的持仓。无影响的计算可以保留，影响判断及范围须可说明。只改变数据错误的修复不等于发现新策略，旧错误结果退出采用依据。

### 3.4 信息进入决策的时间

周度普通信号在每周最后一个市场交易日北京时间20:00固定，行情仅截至该日收盘。公告有可信公开时刻的，时刻不得晚于决策；只有公告日期的财务记录，自公告日之后首个市场交易日09:30起可用。

TTM、同比和其他衍生量的所有依赖输入均须在决策前可用。公开更正只影响其公开之后的决策，无法恢复的修订时间标为未认证，不回填旧信号。来源优先级不改变这些规则。

历史股票池保留后来退市的公司；使用当时身份、行业和交易规则。未复权价用于估值、绝对价格门槛与成交，调整收益只用于明确需要它的因子。真实公司行动仍单独进入账本。

## 4. 与因子无关的经济400池

### 4.1 形成顺序

在每个周度信号时点，重建当时存在的沪深证券，依次应用以下共同条件，再按真实总市值由小到大取最多400只；同市值按代码固定排序。

| 条件 | 固定口径 |
|---|---|
| 身份和权限 | 当时上市的沪深普通A股；使用该次运行明确的板块权限范围 |
| 非金融 | 按历史生效申万一级分类排除银行、非银金融；所需分类未知不新增 |
| 上市时间 | 至少经过250个市场交易日 |
| 已知风险 | 排除ST、退市整理、已明确终止上市等不合格状态 |
| 原始股价 | 信号日未复权收盘价不少于2元 |
| 流动性 | 前20个市场交易日日均成交额不少于1,000万元 |
| 市值 | 当日总市值有效，并满足当时该板块已生效的交易类市值底线 |
| 当日状态 | 信号日正常交易，必要价格和状态有效 |

确认停牌日的成交额计0，来源缺失不能计0。没有适用市值门槛的历史时期不套用后来的规则。基础范围中存在会改变前400名的身份或市值未知时，本批经济池不健康，不发布普通信号。

### 4.2 池与评分的关系

经济池不读取因子分数，也不要求某一财务因子有值。形成400池之后，再检查因子包有效性；不可评分股票不从池外补足。经济合格股票不足400只时使用实际数量，不降低门槛。

池边界保持硬400名。老持仓因排名变化离开经济池，按周度普通退出处理。代码范围、历史风险及经济过滤改变形成新策略规则，不能伪装成预处理微调。

## 5. 因子包准入、评分与缺失处理

### 5.1 因子包可以后定，接入规则现在固定

最终投资因子名单暂不指定。每个包明确全部计分项的公式、方向、单位、观察窗口、有效性、数据依赖、来源政策和信息可用时间，使用少数因子固定等权，不运行中拟合权重、翻方向或临时删除某项。

骨架联调允许使用标识清楚的测试包。测试包与投资包共用资金、执行、风险及账户规则；联调通过不构成投资采用。更换包不改变经济池定义，但其评分有效集和持仓可能变化，必须重新检验。

### 5.2 因子包的两级准入

| 级别 | 必须满足的条件 | 得到的资格 |
|---|---|---|
| 接入研究回放 | 数学定义明确；适用于周频横截面排序；时点与有效性可解释；能够输出分数、无效原因与联合覆盖；不依赖未来成交结果 | 可进入固定账户比较，不代表能部署 |
| 进入投资采用评价 | 完成规定起点、资金、费用及执行情景的完整账户回放；通过联合覆盖和运行持续性要求；实际换手、费用、尾部缺失、与B0的差异及外部替代比较齐全 | 进入第12节资格裁决；不能仅凭单因子IC获准采用 |

覆盖按**当前包全部项同时有效的股票数**计算，不以单因子覆盖率平均或相乘代替。每批完整可评分数须达到可信经济池的80%。例如400只中只有280只全部有效，本批覆盖70%，不健康，即使每个单项分别达到90%。

投资包还须在每个规定历史起点的正常BASE／HIGH运行中满足：**至少95%的应评估周度批次达到80%联合覆盖，且不存在连续3个联合覆盖不足的批次。** 该标准是本版新增的运行可用性要求，不是由历史收益优化的阈值。因全源故障或经济池未知而不能计算的批次单列；未查明前不能删去这些批次，宣称覆盖已通过。

完整账户必须记录覆盖不足导致的暂停、现金和退出。只有单项相关性、理论解释、分组毛收益或短期前向记录的包，不满足投资采用准入。

### 5.3 统一评分

> 单位、时点及经济有效性核对 → 共同评分集 → 方向统一 → 平均并列百分位 → 映射到−1至1 → 包内等权合成

一只股票须拥有当前包全部项的有效值，不按其剩余项重新分权。合法负值和真实极值保留；主流程不叠加截尾，百分位限制数值幅度。并列使用平均名次，恒定因子记0并保留原权重。综合分全相同的批次，不新增买入或进行排名替换；确定资格退出与风险处理仍继续。

主评分不作市值、行业中性化，不自动加入规模因子。评价中展示规模和行业暴露。MAD截尾加Z分数仅为独立标识的研究对照，不得在运行中择优切换。

### 5.4 缺失、无效与不合格

| 情况 | 已有持仓的固定处理 |
|---|---|
| 有效但评分较差 | 按正常周度排名和缓冲处理 |
| 确认分母非法、报告过期等模型不适用 | 在健康周度批次安排普通退出 |
| 个别来源暂缺、版本冲突或事实未知 | 首个健康周度批次保留且不加仓；连续第二个健康周度批次仍不可评分，按持续不可评分退出 |
| 全源故障或全池不健康 | 不套用个别缺失次数进行批量清仓；暂停普通排名交易，必要风险和核账继续 |
| 已确认风险资格失效 | 禁止买入，按风险退出处理 |

“健康周度批次”同时要求经济池可信、联合覆盖达80%。全局故障不累计个别缺失次数；恢复可评分后清除该股计数。上述运行处理不替代第5.2节对长期可用性的准入。

可用缓存仅使用到其失效边界。财务报告期默认最长有效期15个自然月，最终因子定义可规定更严格周期；不能用这一默认值覆盖已确认的未披露风险或无限延期。

## 6. 周度组合、固定金额与资金适配

### 6.1 30只目标与30／45缓冲

首次在有效集内依评分顺序选择30只。后续优先保留经济资格仍合格、评分有效且排名不超过45的老仓，排名越界、离池或持续不可评分的持仓列为普通退出。

按真实保留仓和已知冻结情况规划补位。行业限额不允许纳入某股时，可在信号时点检查后续排名；发布时固定拟新买代码集合。执行时买不到不补选，数量不足留现金。

卖出股数实际归零才释放正常名额。部分卖出、卖单未结束和冻结仓仍占位；未结束的新买委托也占用拟持仓名额。实际被动换股等造成超过30只时照实记录，暂停新增，不删除权益来满足数量。

### 6.2 目标金额与普通调权

以周度截止时本策略真实净资产为基数，股票规划60%，每只中心2%。单股普通权重处于1.5%—2.5%（含边界）保持股数；严格越界才调向中心。少持股时仍按固定30个槽位计算，不把60%重新分给少数股票。

普通目标金额在信号时点固定。执行日净资产上涨不扩大普通目标；真实价格、资金和风险只允许缩减或取消买入。确认的公司行动更新股份基础，但不把保持股数变成重新等权。

信号后发生外部入金、出金或策略间转资，原批普通买入失效；风险按新权益处理，普通名单和金额在下一周重新形成。

### 6.3 买入约束

买入同时受本策略资金归属、券商真实可用现金、已承诺占用、待付费用和税负、60%规划暴露、单股与行业限额、正常名额及成交容量约束。

未成交买单按最大可能成交及费用预留，确认终态前不释放。未成交卖单无可用回款，应收分红不能付款。费用后权益和订单可能全部成交后的风险均需满足约束。

不为凑满30只卖掉原本带内保留仓；但明确风险纠偏优先于带内不动。不为用完现金追加代码，不动用另一策略额度。

### 6.4 首次资金适配

对每个明确“资金＋权限＋因子包”配置，按该次首个信号的名单、参考报价、交易单位及费用作无市场受阻的建仓测算：至少24只非零持仓、原始股票市值占本金至少50%、不突破风险限额。

不通过即该起点配置不启动，不能把其全现金零回撤算作合格策略。启动后因未成交或风险退出低于24只、50%时，不强买或强卖。

10万元与50万元独立评价。10万元不适配不自动否决50万元；实际部署金额另按相同规则验证，不按比例缩放已有净值。

## 7. 风险管理、运行状态和停用

### 7.1 统一计量

风险分母为本策略真实净资产。股票风险包含正常、冻结及仍有股票性质的残余权益；分类变化不使风险消失。行业采用同一历史申万一级分类，未知行业的旧仓不能从集中度中删除。

每日收盘判断风险，执行前和回报后复核当前约束。严重估值或账户事实未知时限制新增，证据充分的减仓继续。首版不承诺全天实时止损；日内复核不伪造为早于事实可用的风险判断。

### 7.2 固定触发与动作

| 风险 | 触发 | 动作和结束条件 |
|---|---|---|
| 确认风险资格失效 | ST、退市整理、明确终止上市等 | 关闭买入，持续退出至完成或触发被证明错误 |
| 价格／市值底线 | 核实后收盘价低于2元，或适用市值底线失效 | 持续退出；价格反弹不自行撤销确认的退出 |
| 单股集中 | 严格超过5% | 减向当前权益的2%，达到2%以内才结束 |
| 行业集中 | 严格超过20% | 降至20%以内，未达目标保持纠偏 |
| 总股票暴露 | 严格超过65% | 降至60%以内，落回65%以下不算完成 |
| 风险退出受阻 | 应风险退出而不能卖出的仓位达到净资产10% | 关闭全部新增，比例低于10%且无其他限制后解除 |
| 回撤预警 | 连续净值回撤达到20% | 预警、展示风险，不改变评分或自动加仓 |
| 应急整体退出 | 连续净值回撤达到25% | 撤销买入、退出全部可处置股票；进入退出并最终停用，不自动恢复 |

真实分红、送转引起的名义价格变化先核对再执行同一2元规则，不临时豁免。资金流不得重置回撤高点。

### 7.3 冲突优先级

> 可信事实与合法交易 → 应急整体退出 → 个股确定风险退出 → 个股超限 → 行业超限 → 总暴露纠偏 → 普通退出和调权 → 普通买入

同股多个卖出要求合并为一个最严格的剩余持仓目标，不叠加卖出数量。被列为退出或风险减仓的股票，本批禁止冲突买入。所有卖出不超过实际可卖数量。

行业与总暴露纠偏不依赖因子分数，在受影响可卖仓内按市值比例减少，冻结部分继续计入。风险纠偏触发后维持至目标线；每次用当前权益和持仓重算，已自然满足目标时结束。纠偏未完成时关闭新增，不依赖10%受阻门槛才停止加仓。

### 7.4 状态及其持续性

| 状态 | 行为 | 退出条件 |
|---|---|---|
| 待启动 | 数据、资金、权限和配置检查，不开仓 | 检查通过且有有效计划 |
| 正常 | 周度普通交易和每日风险核对 | 出现全局限制转受限；25%触发转退出 |
| 受限 | 不新增买入，允许有充分依据的退出、减仓和核账 | 原因消除及目标满足；普通交易仍需有效周度计划 |
| 退出 | 只处理卖出、撤单、公司行动和账务 | 可处置主动股票清空、委托状态确认后转停用 |
| 停用 | 管理现金、残余权益，继续计净值 | 无自动重启路径 |

25%真实触发标记一经产生，不因回撤回落、换年份、换启动日或追加资金清除。即使尚有卖不掉的残仓、仍处在“退出”，采用评价已经视为触发停用。

数据错误导致的误触发可以在证据核正、对账并复验后由人工撤销；实际已经发生的交易、费用和损失不能倒删。真实风险触发后的重新采用按第12.5节处理。

## 8. 执行时序、失败和交易费用

### 8.1 周度与每日运行

| 时点（北京时间） | 行为 |
|---|---|
| 每个交易日收盘后 | 更新事实和权益，形成之后窗口的风险目标 |
| 每周最后交易日20:00 | 固定普通名单、金额及依据 |
| 执行日10:00前 | 核对持仓、未结束委托、资金授权及新风险 |
| 10:00—10:30 | 在本策略串行批次内先卖后买；按真实回款、名额和风险执行 |
| 窗口结束 | 停止新增普通委托，撤销未成交部分，确认状态并核账 |

常规窗口是信号后首个交易日。周内已知风险使用之后首个允许交易窗口，不等下周。执行窗口内才确认的风险只影响确认后的行动，10:30后未完成卖出延续至下一允许窗口；不能声称已经在窗外成交。

### 8.2 期限与部分成交

普通排名退出、池边界退出、买入与调权仅在所属窗口有效；未成交部分到期后请求撤销。经济意图到期与券商撤单确认分开，终态未知仍冻结资金、可卖量和名额，不重复委托。

风险退出与纠偏跨日保留目标，每次按真实剩余数量重计划，不盲目重放旧订单。部分成交逐笔更新，委托级费用合并核对。

普通卖出失败并不强制阻止使用独立已有现金买入，但必须仍有真实空位、共享现金授权及全部风险条件。若风险纠偏未完成、应急退出或存在全局限制，则禁止新增。

### 8.3 价格保护和容量

采用有价格保护的限价委托，不无限追价。具体限价与合法取整、窗口内有界重试由详细设计确定，不改变名单和期限。

单股当日买卖成交金额与尚可能成交的委托金额合计，不超过执行日前20个市场交易日日均成交额的1%。买卖不净额抵消，撤销确认才释放未成交部分，已成交金额保留在当日累计。日均上限不证明盘中流动性足够；风险卖出也不能越过真实可成交性虚构退出。

### 8.4 固定研究费用

佣金率0.025%，每笔有成交委托最低5元；BASE／HIGH单边滑点10／30个基点。适用印花税、过户费等按历史生效规则单列，已经包含在佣金中的费用不重复计算。

最低佣金按同一委托累计成交计算，撤销后重新报单属于另一委托；零成交不产生成交佣金。真实采用前用用户合同及券商清算配置核对和重放。研究费率不等于已确认合同，高成本情景不替代不可成交检验。

## 9. 唯一股数现金账本与资产生命周期

账本保存真实总股数、可卖数量、现金、冻结、有依据的应收、应付和费用。冻结资产仍属本策略但不能再次使用；净资产扣除真实负债。费用从现金支付，不按比例缩减不可交易股数，负余额不截成0。

| 事件 | 处理原则 |
|---|---|
| 分红 | 登记权益、除息应收、实际到账和股息税分阶段记录；到账前不能付款 |
| 送转 | 按条款确认股数及到账、上市、可卖时间 |
| 配股 | 首版不自动认购，不自动付款；不参与的权益影响如实计入，不能当免费送股 |
| 合并、换股、收购 | 按条款转换股数或现金，被动获得的权益继承原持仓的唯一策略归属 |
| 停牌、卖出受阻 | 保留真实持仓、名额、估值和未完成事项 |
| 终止正常交易或残余权利 | 按已确认生命周期转入残余权益，移出正常选股名额但不释放现金、不删除风险 |

公司行动不能由下一日总股本或价格跳变倒推成已发生的免费权益。残余回收未知时列示估值和清算情景，不默认归零或末价全额现金回收。

估值标记为可采用、暂估、无法可靠估值。停牌延用最近价格须保留日期与状态；决定性未知不允许输出无条件风险通过。每笔税费和持有批次归属于唯一的证券所有策略，不存在跨策略争抢同股批次。

净值从真实初始入金开始，包含首日损益和费用。资金转移采用份额化或等价时间加权处理，不把外部现金流当收益，不重置高水位。停用后现金、残仓损失和回收保留至共同评价终点。

## 10. 共享QMT账户：人工协调、串行执行与对账

### 10.1 确定范围及能力状态

本版仅支持“ETF策略＋本股票策略”，证券范围互斥。按范围确定证券、成交、公司行动及直接费用归属，不设计数量分摊、内部成交或净额撮合。

**不认定现有R5、账户适配或qmt_gate已经具备完整共享现金隔离能力。** 首版采用人工维护并确认的资金台账和串行批次；这是本方案需要落实的边界，不是已验收模块。

### 10.2 最小资金记录

只需要一份共同资金记录及两个策略视图。共同记录保存：已确认初始划拨、后续转资、各策略现金归属、未分配现金、已授权未结束的资金承诺，以及尚待核对的公共费用或差异。

每个策略视图包括自己的全部证券、现金、应收应付、费用和净值。共同记录汇总子策略余额，不生成第三套投资收益，也不以全券商资产覆盖子策略权益。

同一计量时点和口径下：券商已记账现金对应ETF现金、股票策略现金与未分配现金之和；券商可用现金还需扣除其实际冻结及其他限制。子策略权益之和与券商总资产比较前，对齐应收、负债和清算时点。已解释的在途差异单列，不能把无法解释的差额塞入某策略来强行对平。

### 10.3 一笔现金只能被承诺一次

每批计划执行前同时满足两道限制：

**策略限制：** 该策略真实归属现金，减去其尚未结束的承诺、必要费用与已知待付款后，能够承担本批订单。

**券商限制：** 券商已确认可用现金，减去尚未体现在券商冻结中的已批准计划占用及必要待付款后，能够支付本批订单。

一笔承诺从“已批准未报单”转为“券商冻结”时只转移状态，不重复扣两次，也不在转移中释放。撤销请求不是释放，成交回款必须已确认可用。ETF卖出回款仍先归ETF，不自动成为股票策略买入资金。

### 10.4 首版执行方式

人工依次批准交易批次，任一时点只允许一方主动下新订单；另一方不得基于同一张旧现金快照同时承诺资金。上批委托已结束并核对后，才开始下批。发生未确认订单或公共现金差异时，不批准新的增风险批次。

小市值策略的已确认应急退出优先于尚未启动的普通买入批次；已有委托须先确认或取消，不能假定不存在。证据充分的必要卖出允许人工优先处理，但每个订单与归属均记录，不突破可卖数量。

本策略仍只在10:00—10:30内执行。人工协调未能及时完成，普通计划到期留现金，风险目标延续至下一允许窗口；不擅自延长窗口。前向记录保留这类真实延迟，验证不通过时不宣称串行方式已经满足策略执行条件。

### 10.5 资金转移与对账

策略间转资只转移已确认、未承诺且满足待付款需要的现金，不跨策略调拨证券。人工确认后同一时点记录转出和转入，总额相等；双方份额化处理资本变动。未实际确认的额度调整不改变净资产或购买力。

在开始交易、批次结束和日终核对：证券数量与可卖量、已确认成交和费用、未结束委托与占用、现金归属、公司行动及净资产。证券直接按互斥范围对账，不再核算同股份额分配。

ETF侧必须能够按**自己的证券和划归权益**形成或校核计划。若当前适配把全券商资产当ETF自身资产，不能仅靠“不同时下单”继续运行；先用独立归属快照和额度核对补齐最小边界，未补齐时只做研究／清单，不启用两策略共享实盘。这是局部输入与核对要求，不要求重构整个ETF系统。

## 11. 回放时间轴、固定起点及压力情景

### 11.1 一套决策语义，三类执行证据

| 模式 | 固定时间原则 | 能支持的结论 |
|---|---|---|
| 日线开盘代理 | 普通名单来自原周度截止；用于该次代理成交的信息必须在代理成交前可得。执行日开盘状态只作成交可行性处理，不重新排名 | 历史诊断，不能认证10:00—10:30的执行 |
| 分钟窗口回放 | 使用10:00—10:30内当时可见报价、状态和真实顺序：卖出、回款、买入 | 支持对应窗口的模拟，仍不等于真实排队保证 |
| 真实成交观察 | 以券商确认的委托、成交和资金时点为准 | 核对本机能力及实际执行，不回填历史信号 |

日线开盘代理不得使用10:00才取得的新信息，再假设9:30或此前开盘价成交。迟到风险只能作用于之后的代理执行时点。不能同时用全日成交量、全日最高最低价判断早盘一定可成交；其用途限于后验诊断或明确标注的保守情景。

日线代理的同价卖出回款与买入只是诊断性简化，不能据此证明实际资金顺序可实现。若差异会影响采用结论，需要分钟或前向证据；日线代理通过不直接进入部署。

### 11.2 四个预设新资金起点

每一候选配置固定使用以下四个起点，均独立从现金开始，沿同一数据、参数和规则回放到共同终点：

| 起点 | 定义 |
|---|---|
| A0长历史 | 2011年内首个周度截止日入金并固定首个信号 |
| A1 | 2016年内首个周度截止日入金并固定首个信号 |
| A2 | 2021年内首个周度截止日入金并固定首个信号 |
| A3 | 2024年内首个周度截止日入金并固定首个信号 |

周度截止仍为当周最后市场交易日20:00，首次执行在之后首个允许窗口。入金时单位净值为1，首日费用和损益不遗漏；因子需要的历史预热位于入金前。

共同终点D在查看候选成绩前，按本轮冻结且完整的共同数据确定，全部起点和情景使用同一D。不得因为中途停用而缩短区间，不得改选一个恰好未触发停用的新起点。2015年所在长历史压力阶段不得通过只保留2016年以后而排除。

某个规定起点缺少必要的可信输入，记录“证据不足”，可继续局部诊断，但不以删除该起点取得完整采用资格。四个起点是固定的有限检验，不代表覆盖所有可能建仓日，也不是新盲测。

10万元与50万元分别形成候选资金配置；只有资金适配通过的配置继续完整评价。实际部署金额仍须按四起点验证。不是要求两种金额同时通过才能采用其中一种。

### 11.3 四种固定成本与执行情景

| 情景 | 定义 |
|---|---|
| S0 BASE | 固定规则和对应执行时钟，BASE成本 |
| S1 HIGH | 与S0相同，使用HIGH成本 |
| S2 HIGH＋延迟一天 | 每个普通批次、每段风险目标的首次允许执行时点延迟一个市场交易日；普通单窗口期限同步移动，之后不因每日重计划重复延迟 |
| S3 HIGH＋风险卖出受阻三日 | 从该段风险目标首次允许执行的交易日起，前三个市场交易日禁止其作用范围的股票卖出；第四个交易日起仍需满足窗口、停牌、涨跌停、容量及其他真实约束 |

S2适用于普通、个股、行业、总暴露和应急目标。原普通名单与金额不因延迟而重选；期间新风险按真实可得时点优先裁决。已经不需要的风险目标不被强制制造交易。

**S3明确覆盖组合共同受阻：** 个股风险作用于该股；行业纠偏作用于该行业；总暴露纠偏与25%应急整体退出作用于本策略全部股票。共同受阻时这些股票的普通卖单也不能绕过阻断。应急退出后，现金不假定增加，全部受阻仓位、公司行动与后续损失持续入账。受阻范围仅为本股票策略，不虚构ETF也发生同样风险。

每段目标的三日阻断只启动一次，日常重算不滚动重置；独立新风险段发生或与既有段重叠时如实合并其限制。S2与S3分别回放，不相互叠加，不在看到结果后追加更多冲击强度。

全部情景使用相应历史价格演变，不额外假设固定跌幅。风险识别到下一10:00窗口的等待、三日阻断以及窗口后继续无法成交的时间都进入账户路径。无成交不等于无损失。

### 11.4 输出

输出完整净值、股数现金、交易费用、未完成事项、状态和触发原因；按起点和情景列明：是否启动、首次停用触发日、实际运行时长、可交易在场比例、正常信号可用率、平均暴露、最大回撤、费用后年化以及停用后资产变化。

现金期与残余权益保持至D。停用前收益可作解释，但不能替代全期收益，也不能被用来恢复采用资格。

## 12. 评价、研究推荐与重新采用

### 12.1 固定对照

| 角色 | 规则 |
|---|---|
| B0规模基准 | 同一经济400池内按市值排序，30／45缓冲及相同资金、风险、费用、执行；不要求评分因子有效 |
| B1主候选 | 当前固定因子包、百分位等权评分、30／45缓冲 |
| B2缓冲对照 | 同B1因子包和有效集，但不设置45名保留区；其余一致 |

B0不适用因子覆盖门槛及因子持续缺失退出。B0与B1差异包括因子覆盖和选股，不能全部归于独立预测能力；共同评分集的规模归因单列。B2仅检验缓冲的完整作用，不在编码阶段择优替代主方案。

外部替代固定选择与风险方向相关、实际可投资且数据可得的ETF及真实现金配置，选择依据在看结果前记录。共同产品存续期单列，指数历史不冒充ETF上市前可交易收益；ETF资产不并入本策略净值。

### 12.2 四类结论，不混淆历史赚钱与当前能用

| 结论 | 条件与含义 |
|---|---|
| 工程可继续 | 规则及实现检查通过，可进入详细设计或下一项研究；不涉及投资批准 |
| 证据不足 | 数据、估值、覆盖或执行能力尚不足以完成规定评价，不进入采用名单 |
| 不采用该候选配置 | 已确认启动不适配、规定回放触发停用、风险不合格或缺乏经济价值 |
| 可供采用评审 | 全部硬条件通过、经济比较完成、外部实施条件已验证；仍需用户另行授权真实使用 |

### 12.3 先判资格，再排收益

对每个“完整规则版本＋因子包＋资金＋权限”配置，依次检查：

**第一，真实性。** 来源政策、历史可用性、账户和估值可解释；决定性未知不以有利假设代替。

**第二，可运行性。** 四个起点首次资金适配通过；因子包满足第5节联合覆盖和持续性标准；执行与共享现金边界能够落实。数据暂停及空仓不能被删除后宣称运行正常。

**第三，存续资格。** 在任一规定起点的S0—S3中，只要根据可信数据和规则真实触发25%应急退出，**该候选配置退出本轮“可持续采用”名单**，即使后续全现金使其年化为正、最大回撤仍低于30%。保留全期业绩，只用于历史过程与失败归因。不以其他起点幸存来覆盖失败。

**第四，风险。** 四起点、四情景连续最大回撤均不超过30%，不四舍五入通过。若触发停用前后受阻损失使回撤超标，同时记录存续失败与风险失败，而不是只记较轻的一项。

**第五，经济价值。** 仅对上述条件全部通过的候选，定义其稳健年化为四个起点的BASE／HIGH费用后年化中的最低值。该值须大于0；再按稳健年化从高到低形成研究排序，同值依次优先较小最坏回撤、较低交易成本和较少因子。

费用、换手和相对B0增量必须来自完整账户，不以IC或毛标签排序替代。对长历史BASE与HIGH均不降低年化、且收益或回撤／交易负担有改善的包，可以形成明确增量推荐；仅表现为“收益减少、风险降低”等相互取舍的包，单列为**投资取舍待决定**，不由程序自动宣称胜出。若B0本身触发停用，B1的存续改善如实计为运行性证据，不据此宣称纯因子alpha已成立，还须完成可投资ETF替代比较。

排序只是研究推荐，不是交易授权；未通过前四项的候选不与幸存候选争夺冠军。既有历史已被观察，所有结果仍为有约束的探索与验证，不宣称新的独立盲测或未来收益保证。

### 12.4 固定60%等基线失败时怎么办

已核准的完整回放在任一强制起点／情景触发真实停用或超过30%，结论为**本候选配置不采用**。不将60%自动下调，不关闭应急，不换起点，不删除尾部事件，也不借ETF资产稀释。

只有确认是数据或实现错误，才修复并重放原矩阵；若规则本身需要调整，则另立明确的新版本、说明改变的问题并完整复验。不能在本版内连续搜索仓位直到29.99%。全部候选失败时允许没有策略采用。

### 12.5 重新采用

真实应急停用后，原运行不自动恢复，换版本名称、重新入金或采用另一个有利历史起点都不是重新采用依据。

重新申请须具备：对触发原因的明确归因；有实际内容且针对问题的规则／因子修订，或可证明的错误修复；原固定起点与压力矩阵的完整复验；因变更受影响的数据、实际费用、执行和共享现金能力验证；用户对新投资配置的明确采用决定。既有损失和运行记录保留。

对于结果间收益与风险的投资取舍，用户可另行选择，但不得借取舍豁免真实性、共享现金、存续或30%硬条件。若要改变硬条件，必须先明确修订策略基线，不能让排序程序替代该决定。

## D02. 公共数据合同与精度

### 2.1 原子类型与硬门槛的精确算术

`Money`和`Price`从十进制字符串读取；实结现金/费用按原费用合同到分、`ROUND_HALF_UP`，价格按tick。股数是非负整数。不能将真实金额经float往返，也不接受NaN、Infinity或布尔值冒充数字。

**两种数值用途严格分开。** 已结算/按合同量化后的货币和价格保存其完整有限十进制；统计、展示及非代数运算可使用50位Decimal。`units、NAV、HWM、DD`及排名采用`ExactRatio`，即任意精度整数分子/正整数分母，零统一0/1、始终约分。把十进制转有理数时直接由十进制系数和10的幂得到精确比值，不先做Decimal除法。

股票市值、权益及买卖预览中用于硬比例判断的加、减、乘、除，也以这些已量化输入的精确比值计算；只有实际费税取整点按FeeProfile量化。不能先以50位舍入出一个权益/NAV，再声称把该舍入值转成有理数已经修复精度。有限十进制的金额和市值精确求和可继续以完整十进制存储；比例不要求展开成有限小数。

所有硬条件使用整数交叉乘：`x/y >= a/b ⇔ x*b >= a*y`（正分母）；对于DD阈值t，使用`NAV <= (1−t)HWM`；30%合格使用`NAV >= 0.70HWM`，方向及等号严格遵从第0节常量表。禁止epsilon、显示值回读、先四舍五入比例或仅靠提高精度补救。

序列化统一为`{"num":"300004","den":"3"}`：分子分母均为十进制整数字符串，禁科学记数、前导零、负零、负分母及未约分输入。该表示同时用于精确排名、份额、NAV/HWM/DD；显示小数另命名`*_display`，只读且不进入决策或恢复。Schema校验形状，业务校验gcd、正负约束及缓存一致性。 非日终快照的NAV可高于上一正式日终HWM；此时缓存比值`dd=1−NAV/HWM`可为负，只作中间投影，不能据此重写正式高水位或触发新日终风险。正式日终先更新HWM再计算非负DD；恢复不得以HWM小于盘中NAV为由拒绝正确快照。

因子原始统计值如来自浮点计算，先按该FactorSpec指定的量化精度规范成Decimal字符串，再进行精确排名；这与对账户风险线使用epsilon不同。对账中每个已经解释的外部显示字段可以有0.01元舍入差，但不能把该显示容差用于资金授权、份额或风险门槛。

### 2.4 返回值与错误

全部核心函数返回`Result(value, status, reason_codes, input_refs)`。可预期业务阻断不用抛异常伪装程序错误；字段格式不合法、重复事务内容冲突、违反守恒用硬错误并停止该账户增风险。

关键原因码统一：`SOURCE_CONFLICT, SOURCE_STALE, BASIS_MISMATCH, RULE_UNKNOWN, POOL_UNCERTAIN, JOINT_COVERAGE_LOW, FLAT_SCORE, FACTOR_UNAVAILABLE, MODEL_INAPPLICABLE, INSUFFICIENT_CASH, SLOT_BLOCKED, RISK_ACTIVE, TAX_UNKNOWN, CAPACITY_EXHAUSTED, ORDER_STATE_UNKNOWN, CAPITAL_CHANGED, VALUATION_UNKNOWN, CASH_RECONCILIATION_FAILED, STARTUP_UNFIT, RETIRED_TRIGGERED, SCENARIO_INCOMPLETE`。

## D03. 时钟、来源选择与历史版本

### 3.1 日历和事件排序

使用经核验的沪深市场交易日历；不以星期一至五代替交易日。`week_end`按Asia/Shanghai自然周分组取真实最后市场日，截断在数据末尾的半周不能当完整周。四起点取对应年中第一个`week_end`，而不是该年的第一个交易日。

保存UTC时间及市场日期，所有展示转北京时间。来源时间无时区且无法确认时该记录不可进入执行。

同一时刻事件排序固定：①已有登记依据的除权/股份上市/可卖释放；②此前委托的真实成交和终态；③现金实际收付与资本转移；④行情/事实更新；⑤日终登记权益快照及NAV（必须已经处理当日成交）；⑥风险裁决和周度计划；⑦批准、报单或撤单；⑧快照。登记日锁定股数不是盘前事件，不能先登记再遗漏收盘成交。来源有更细序号时先遵从来源序号。排序不得让本次新委托消耗在它之前发生的成交。

日终净值采用该交易日收盘标记与截至日终核账截止已确认的当天权益，核账截止固定20:00。周度日先完成日终权益/风险，再形成20:00普通计划。20:00后新信息只影响下一允许行动；迟到公司行动可能修订会计事实，但不得伪造已经按它下过单。

### 3.2 信息可用时间

- 有可信公开时刻：`available_at >= public_at`，并满足所用来源可提供时刻。
- 财报只有公告日期：`available_at = 公告日后第一个市场日09:30`；财务`end_date`不是可用日。
- 衍生指标：`available_at=max(所有依赖available_at)`；修订版不回填过去。
- 实时账户或报价：以程序收到并确认的事实为准，使用`max(occurred_at, received_at)`作决策可见边界。
- 历史重建的`received_at`可以是本次下载日，但必须保留重建依据与版本可信状态；不能将当前名称、股本、行业当成历史。

### 3.3 来源确定算法

先规范身份、交易日/报告期、单位、原始/调整价格及股份基础，然后按下表一次决定。

1. QMT具备所需历史语义且该条有效，Tushare缺少或一致：取QMT。
2. QMT缺字段、缺历史语义、过期或已经证明错误：有同口径有效Tushare则取Tushare，写`SUBSTITUTE`事件和原因；否则未知。
3. 双方均表面有效但实质冲突：不按优先级掩盖冲突，返回`SOURCE_CONFLICT`；证据核定后再恢复主辅政策。
4. 仅展示精度差：把值解释为中心值±半个来源量化单位；同基础且区间相交视为可解释舍入，采用QMT中心值，不平均。区间不相交须核查。
5. 券商余额、股数、委托、成交、实扣费用只取已确认账户事实，Tushare不能替代。

不能因QMT的一条历史值缺少修订时点而使用它覆盖更有历史证据的Tushare记录。来源选择保存于统一观测表，因子、风险和账本不能各自选来源。

### 3.4 字段标准化

| 标准字段 | 口径 | 入口及处理 |
|---|---|---|
| `raw_open/high/low/close` | 未复权元/股 | QMT `dividend_type='none', fill_data=False`优先；Tushare `daily`补充 |
| `reference_preclose` | 交易所除权参考价 | 与前一交易日真实收盘分开保存，不当现金分红 |
| `volume_shares / amount_cny` | 股 / 元 | Tushare `vol`手×100、`amount`千元×1000；QMT具体接口单位依其已核验映射，禁止按字段名猜 |

### 3.5 财报版本与衍生量

对于`security_id, statement_type, period, consolidated_scope`，只在`available_at<=cutoff`的版本内取最新公开版本。相同公开时刻有初始/修订多个值时，使用有明确版本关系者；只有标记但无法确定更正时点时，不把新版放入旧时点。完全相同重复行可去重，内容冲突不能取返回顺序第一行。

因子最新报告期以所需报表中已公开的最新期间为锚；该期间必要依赖缺失或无效时输出原因，不悄悄退回表现更好的旧季度。明确尚未公开的新期不是缺失，不抢用未来数据。各期合并范围或可比口径不一致，返回`BASIS_MISMATCH`。

累计转单季：Q1直接用累计；Q2、Q3、Q4分别减本年上一季度累计，所有输入都须已公开。TTM可采用`当期累计 + 上年全年 - 上年同期累计`，Q4直接用全年；四个单季求和应与此同口径相等，否则拒绝该量。

同比、现金流/资产等最终因子公式随包输入；公共数学规则固定：分母为0或经济上要求为正但非正，则`MODEL_INAPPLICABLE`；合法负利润保留，不能改为0。财报有效截止为报告期加15个自然月的当天结束，包可更短；超过为过期。

### 3.6 修复影响与重放

任何来源、身份、版本、单位、公司行动修复，记录最早受影响的可见事实及依赖。因子修复从最早受影响周度决策前的账户快照开始；账务事件修复从该事件前开始；全部后续路径、相关起点和情景重算。

修复前结果保留并标`SUPERSEDED_INVALID_INPUT`，不得与修复后拼接。实时真实已发生交易不能删除；迟到修正记录真实差异，另作历史对照回放。未知问题可能改变选股、净值或资格时，不输出无条件通过。

## D04. 经济400池、健康性与三值资格

### 4.1 资格判断

每个原子条件返回`TRUE / FALSE / UNKNOWN`。任一条件已确认FALSE即可确认不合格；只有全部TRUE才合格；剩余为UNKNOWN。上市250日按`calendar.index(signal_date)-calendar.index(list_date)>=250`，不是成交天数。

信号ADV20取包含信号日的最近20个市场日之和÷20。真停牌有明确状态时金额0；供应商缺失使该窗口未知。执行日容量ADV20另取**执行日前** 20日，二者不得共用错误窗口。

市值底线用RuleBook的板块、日期区间。`NOT_APPLICABLE`表示已证实该期没有适用底线，允许通过；`MISSING_RULE`表示不知道，有关决策不能通过。金融行业过滤、证券身份和风险状态同样不能依当前名称猜测。

### 4.2 未知是否影响前400

将确认合格者按`(总市值, 标准交易代码)`排序。若满400只，边界为第400条二元键；UNKNOWN对象若有已确认且大于边界的市值键，或其他已知条件已排除，可记录为无关未知；否则它可能改变池，本批`POOL_UNCERTAIN`。不足400且仍有潜在合格未知，也不健康。

不允许用“上个月它很大”推断今天不影响边界。空池是一个可计算的经济结果，但不能定义`0/0`覆盖为100%；记`EMPTY_ECONOMIC_POOL`并暂停新增。初次启动空池不合格，运行中不能删除旧持仓。

### 4.3 稳定身份与残余

400池与当前正常持仓分开；离池是普通退出理由，不能从账本删股。后来退市只用于生命周期核账，不提前过滤历史。被动换股所得继承原股票策略归属；如破坏用户给定证券互斥前提，保留真实权益并暂停共享新增，交人工修正范围，不建立同股分摊逻辑。

## D05. 因子包、百分位、覆盖与计数

### 5.1 因子计算合同

`compute_factor(spec, pool, cutoff, facts) -> {security_id: FactorValue}`。`FactorValue`含`value, status, reason, dependencies, max_available_at, expires_at`。必须是纯函数：不读账户未来收益、不改变数据、不访问系统当前时间。最终包未给出时只加载`TEST_ONLY`固定夹具，报告不能出现投资包已采用。

需要的函数由代码登记名指向实现，不在配置里`eval`任意表达式。新增实际因子必须带单独公式、边界、手算例和前缀不变性测试；不改变账户/风控/执行模块。

### 5.2 联合集合

`U`为经济池，`J={i∈U:所有包内因子均VALID且未过期}`。`joint_coverage=|J|/|U|`，不取各项均值或乘积。健康普通批次须池可信、`|U|>0`且`5|J|≥4|U|`。

进入联合集后，各因子都在**同一个J** 上排名；禁止一个因子用400只、另一个用320只再合成。一股少一项即不在J，不按剩余因子重权。

### 5.3 精确评分

设包有K项，J有n只。将反向项取负后升序排列，最低优先分最低。相同有效数值使用平均并列名次`r_ij`，名次从1到n：

`z_ij = 2(r_ij−1)/(n−1)−1`（n>1）；n=1时z=0。

可全程使用整数：并列块占位a…b，则`2r=a+b`，`z=(a+b−n−1)/(n−1)`。综合`S_i=(Σ_j z_ij)/K`，比较用分子分母交叉乘，不用浮点epsilon。同综合分按标准代码升序；不同来源返回顺序不影响输出。

一项常量因子全部z=0，K不变。所有综合分相同，则`FLAT_SCORE`：本批不新增、不补仓、不做评分/代码顺序替换；保留确认资格退出、持续不可评分退出、无需排名的普通减持和独立风险。对仍合格老仓，截止权重>2.5%生成固定中心金额的`TARGET_AMOUNT`，同时标`prohibit_buy=true, reason=FLAT_SCORE_REDUCE_ONLY`；权重≤2.5%保留股数，低于1.5%也不补买。执行时只允许向原2%金额目标减少股数，若报价变化后差量转为买入则不行动，不能反向补仓。B0仍按市值/代码排序，不受评分恒定限制。

主流程无winsorize、无Z-score、无市值/行业回归；百分位不能拿来覆盖原始数据质量错误。研究对照必须另设配置和结果身份。

### 5.4 个别不可评分计数

对实际持仓逐只维护`missing_healthy_count`。每周只更新一次，由`decision_id`防重：

1. 全局不健康：计数不增、不清，暂停普通排名及调权，保留确定资格退出与风险。
2. 健康且该股当前包可评分：清0，按排名处理。
3. 健康且确认模型不适用（如分母非法或过期）：本批普通退出，不等两周。
4. 健康且来源暂缺/冲突/未确认：count+1；第1次HOLD_NO_ADD，第2次及以后普通退出。
5. 已确认风险不合格：风险退出优先，不依赖缺失次数。

一个健康周、两个故障周、再一个健康但仍缺失的周，计数为1、1、1、2；故障不制造批量退出。真实恢复可评分才清零。

### 5.5 包级长期可用性

应评估周为入金截止至D间所有完整周度截止，不能因空仓、停用、失败而删周。BASE/HIGH逐起点统计：健康周比例≥95%，联合覆盖不足连续长度≤2。即使已停用，离线数据可用性诊断仍计算；它不改变停用后持仓。

全源或经济池未知周记`UNASSESSED`，保留在分母，评价为证据不足；对已知覆盖<80的周计BAD。不能把UNASSESSED当健康，也不能把明确BAD改成数据未知来规避失败。先列已确认失败，再列未解决证据，不用单一布尔吞掉原因。

## D06. 周度意图与普通组合算法

### 6.1 计划生成输入

读取截止时已核账账户、未结委托、经济池、评分、风险段、现金归属及权限。账户未对齐或历史事件未知影响E时不发布可执行普通计划。已有真实持仓永不因不在输入分数表而消失。入金或报单确认导致真实负余额时照实记录并限制新增，不以0截断掩盖已经发生的损失；不因为本地检查失败而拒记可信券商成交。

每股普通模式仅有`HOLD_SHARES / HOLD_NO_ADD / EXIT / TARGET_AMOUNT`。整批保存`E_decision`、`capital_revision`、执行窗口、固定买入代码及顺序；持股锁定保存股份基础，确认送转时转换该基础，不重新定权。

### 6.2 形成保留、退出和补位

按以下顺序，无配置择优分支：

1. 风险全退出/残余权益从普通选股流程隔离；仍保留账本和风险占用。
2. 只有确认经济不合格、确认离池、确认模型不适用或计数达到持续不可评分规则者安排EXIT；因池/数据未知无法确认是否离池时为HOLD_NO_ADD，不构造EXIT。
3. B1合格且可评分的原持仓名次≤45保留，>45退出；B2边界换为30；B0按市值名次30/45且不使用因子缺失规则。
4. 暂缺一周或事实未知的旧仓`HOLD_NO_ADD`并占一个槽。已知冻结、未结束卖单、在途新买占用相应槽位；同证券只计一次。
5. 名单层可假设未被冻结的计划退出完成来形成补位意图，但执行前必须重新数实际空位。计划里写退出从来不产生真钱或真实空位。
6. 依当期排序扫描非持有候选，使用规划后保留市值和新股`0.02E_decision`检查行业20%与槽位；行业不允许则在信号时点跳过该股继续扫描，记录原因。
7. 发布固定的新买集合；执行阶段不得再扫描补充。名单可不足30，不扩池、不放松覆盖、不把预算分给少数股票。

已有计划期内未确认委托时，禁止新普通增风险批次；必要风险处理走独立路径。已持有证券因部分卖出尚有1股也占槽；若被动换股造成正常证券超过30，只记录并禁增，不按代码顺序删权益。

### 6.3 普通金额与买卖方向

`target_i=0.02×E_decision`。截止时`value_i/E_decision∈[0.015,0.025]`则HOLD_SHARES；越界则TARGET_AMOUNT。新股TARGET_AMOUNT、退出目标0。

执行时目标金额不乘账户涨幅。对TARGET_AMOUNT，以当前合法原价估值m和实际股数q计算`delta_value=target_i−q m`；普通增量数量向不越过中心的方向取整。因隔夜涨跌可能改变TARGET_AMOUNT的买卖方向；这是固定金额目标的明确含义，不重新选股。HOLD_SHARES不因隔夜价格变化自动转普通补仓，风险可覆盖。

同一批对某股已发生卖出或风险减仓，则该批将其加入`no_buy_in_batch`，防止随后价格反弹或风险解除触发冲突补买。确认资本转移后整批普通买入失效，**已发出的对应买单也须按D09.4请求撤销**，不是只禁止下一笔提交。普通EXIT仍按剩余股数退出；普通TARGET_AMOUNT仅在按原固定金额解析仍为减持时保留，不因资本流改写普通金额或产生新买入；风险另按当前E重算；下一周才形成新的普通金额。资本流与竞态真实成交照实入账，撤销确认前预约不释放。

### 6.4 行业规划不等于已成交风险消失

信号层使用预期退出后的结构选择名字；执行时用当前真实持仓、全部未结买单和实际费用重新检查。若原行业仓卖不出，不能用规划值为该行业新增。旧仓行业未知时不从风险里删除：暂停全账户新增，核清历史行业后再恢复，不让它落入一个不受20%限制的“其他”桶。

## D07. 统一账户预览、费用后约束与数量取整

### 7.1 一个权益公式

任一一致估值时点：

`E = C_book + Σ_i(q_i × m_i) + AR_cash + AR_other − AP`。

`C_book`包括已归属但冻结的现金；冻结只是可用性限制，不能再次扣净资产。`AP`包括已经确认或按本费用合同已发生而未清算的费用/税负。尚可能发生的未卖股息税仅为购买力预留，不同时当已发生负债。残余权益不得从E或股票风险中隐去。

核心不变量：同一事件的权益影响只记一次；交易、派息、分红税清算与预约冻结有不同分录。估值UNKNOWN时仍可记录实际股数和现金，但不能发布可信E和风险通过。

### 7.2 费用后买入预览

已有股数q，当前同口径估值m，候选买入数量b、保护价p，预估新增费用f。保留当前持仓估值基础，不把高限价自动记成已有股票盈利：

`E_after = E + b(m−p) − f`；`V_i_after = V_i + bm`。

未结束买单按全部成交的数量、保护价和**尚未入账** 费用同时计入；未结束卖单不得预扣股数或预加回款。对本次报价时点逐项要求：

- `E_after>0`；策略现金与券商可付款双门均通过；预留不重复。
- 总股票价值≤`0.60 E_after`；单股≤`0.05 E_after`；各行业≤`0.20 E_after`。
- 当前普通目标金额不能增加，实际名额、容量、权限、可交易性有效。
- 当前全局限制、风险纠偏或EXITING/RETIRED时不得买入。

本预览保证的是当前报价和保护价假设下的约束，不保证未来跳空后仍满足。实际成交/报价变化后重新核查。不同价格场景不能混用分子分母。

按名单顺序处理：先当前持仓允许补仓的缺口，再按固定评分顺序处理新买；同类按固定评分/代码顺序。每次选最大合法、满足全部约束且不超过目标缺口的数量。每笔确定后锁定相应资源，再考虑下一笔；不得先给每只独立算“最大可买”后一起报单。

### 7.3 数量域：申报与成交分开

`TradeRule`提供`buy_min, buy_step, sell_min, sell_step, allow_full_odd_exit, max_order_qty, tick, buy_settlement, tax_date_rule`。数量约束检查的是**本次申报差量**，不是最终持仓数。

采用合法数量集合的保守子集：

- 买入：`{0} ∪ {buy_min+k×buy_step}`且≤数量、金额、最大单量上限。
- 普通部分卖出：`{0} ∪ {sell_min+k×sell_step}`且≤可卖量；如真实全部持仓可卖，允许依RuleBook一次性全部卖出零股。
- 已确认部分成交可以少于最小申报单位；不能以“成交50股不是一手”为由拒绝真实成交。新挂单剩余量须重新满足申报网格：例如原单买300、已成50、确认撤余250后，主板重报最多200，不能重报250，也不能超目标凑300。
- 主板100股步长、科创板最低200股并逐股递增等，均由**对应日期的已核验RuleBook** 提供；例子不是覆盖2011—2026的完整规则表。

普通补买/减持取不越过目标的最大合法差量；不足最小量则延期并保留原因。风险减仓取满足风险目标的最小合法卖量，必要时因最小单位少留于中心值，不能借此加仓。若全部合法可卖量仍不足达到目标，则卖到合法上限、风险段继续，不伪报已完成。

`mature_quantity`指已满足交收/上市条件的总可转让股份，尚未扣订单预约；`broker_can_sell`为券商返回的已扣其冻结后的可用股数。最终`free_sell = min(mature_quantity−全部本地未结卖量预约, broker_can_sell−已批准但尚未体现在券商冻结中的卖量)`，两项均不得为负。规范对象的`sellable_quantity`就是此free_sell；不能再减一次券商已冻结卖量。初次可卖映射未核验时，禁止猜测加回冻结量。

### 7.4 费用后风险卖出：不得只卖“超标金额”

若某作用范围股票价值V，权益E，希望降到比例r；在简化的卖出价等于估值、费用=`kx+F`时，需满足：

`V−x ≤ r(E−kx−F)`，所以 `x ≥ (V−rE+rF)/(1−rk)`。

实际实现不直接套这个简化式，使用`preview_sell(数量向量)`计算保护价、费用和新增税负后的真实分子分母，再检查目标。

示例：E=100,000，股票66,000，目标60%，每股10元，示例费用=卖额0.1%+5元。卖600股后股票60,000、权益99,989，股票比例仍>60%；100股步长下至少卖700股。冻结股票的股数不能为了支付费用按比例缩小。

### 7.5 行业及总暴露的比例减仓算法

作用范围包括冻结仓和残余权益，资金/名额不因不可卖而移除。可分配卖量仅来自当前有合法卖出能力、价格依据、容量余量的正常仓。

采用一个确定的量化比例算法，不依赖因子分数：

1. 先合并更高优先级的目标，得到当前已规划累计卖量Q；一次预览按每证券一个合并委托计算费用，不重复收多份最低佣金。
2. 对作用范围每只可卖仓，令`a_i`为D07.3算出的free_sell再扣除本轮前序已规划、尚未重复预约的卖量。其可减少市值为`a_i m_i`。
3. 每只生成使**合并申报量Q_i+q_i** 合法、且不超过可卖/容量/单笔上限的追加卖量序列，标记比例`q_i/a_i`；不是将任意追加量当成独立合法委托。用最小堆合并各比例；同一比例的全部证券一起推进，同价位再按代码固定顺序。这相当于逐步按可卖市值相同比例减仓，并处理交易单位离散性。
4. 每推进一组，重新用**合并后** Q、费用、税和保护价计算作用范围剩余价值及E_after。遇到第一个全部满足目标的向量即停止。
5. 若所有可卖量用尽仍不满足，输出该最大可行卖量、`TARGET_UNREACHABLE_NOW`及未达差额；风险段继续。
6. 行业逐个按行业代码处理，然后处理总暴露。所有结果按证券合并，不能把个股、行业、总仓三份卖量简单相加。

该算法在连续数量下对应比例减仓，在整数单位下给出唯一结果。实现可用等价优化加速，但必须逐例对照本定义，不能改用“先卖分数最低的”。

**费用闭合复核：** 行业或总暴露的额外费用可能使先前刚满足的单股2%再次超线。完成一轮优先级处理后，以全部合并卖量和只计一次的费用重新检查所有有效风险目标；若仍超线，按同优先级只增加合法卖量，循环至全部满足或本轮数量不再变化。每次至少增加一个有限合法数量档，因此算法终止。无进一步合法数量时标未达目标，不能以“前一步曾通过”输出完成。

### 7.6 初次资金适配

每个固定起点先在截止时的固定名单与当日原始收盘价上作一次无市场受阻建仓测算。应用合法单位、费用后预算、行业限制；不应用假想卖出回款，不从未入选名单追加股票。

24只及50%条件按`非零持仓数`和`Σ股数×原始参考价/入金本金`检查，不把滑点成本计入股票价值。BASE/HIGH各自检查，只有通过者继续该单元完整回放。明确信号不足或已知资金不适配为`NOT_STARTED_UNFIT`；必要数据未知为`NOT_STARTED_UNKNOWN`。不得等待一个后来更有利的首周再启动，也不能将未启动的现金序列计作成功。

## D08. 风险段、运行状态与冲突裁决

### 8.1 风险观察与计量

正式日终净值高水位每日更新，现金流前后使用同一单位净值。EOD产生V5规定数值风险；执行前及回报后用当时可信原始估值复核当前约束和已存在目标，确认的新风险事实可立刻生效。数值回撤采用本策略同一单位净值及已记录高水位，不创建一个独立日内收益账户。

本详细设计限定：**20%/25%的新数值触发以正式日终连续净值为准**；执行前和每次回报后复核个股/行业/总暴露、资金、可卖性以及已经生效的风险段。新的明确ST等事实退出可以立即形成，但不新增一套以日内高点为基础的回撤止损，也不以盘中暂估净值另设25%预停开关。盘中现值可展示，不能回填为前一时刻的日终触发。此为V5“每日收盘判断、执行前后复核”与“首版不承诺全天实时止损”的固定采样解释；未来改成盘中回撤触发属于经济规则变更。

对日终估值不可靠的持仓，E不作为通过依据，新增关闭；事实充分的风险卖出继续。主资产风险采用总股票市值，不能用相关性模型将冻结仓的风险打折。

### 8.2 各风险段的键与持续规则

| 类型 | 唯一键/作用范围 | 触发与目标 |
|---|---|---|
| `SECURITY_EXIT` | 证券＋已确认风险事件 | ST/终止上市/价格<2/市值底线等；目标0，反弹不自动撤销 |
| `SINGLE_REDUCE` | 证券＋段序号 | >5%触发，≤当前E的2%才结束 |
| `INDUSTRY_REDUCE` | 申万一级行业＋段序号 | >20%触发，≤20%结束 |
| `TOTAL_REDUCE` | 本股票策略＋段序号 | >65%触发，≤60%结束 |
| `EMERGENCY_EXIT` | 本配置唯一停用段 | 日终DD≥25%；目标全股票退出，无自动复活 |

同一段每日重算不生成新`episode_id`。目标已自然满足可结束纠偏；证券确定退出只在股数处置完成或触发证实为错时结束。应急真实触发不可自然解除。S2/S3压力附着在段上，不能每日重置。

### 8.3 两级禁买集合：风险模块唯一输出

`detect_risk/resolve_intents`在同一账户/报价修订上输出`RiskDecision.global_buy_blocks`和`security_buy_blocks[security_id]`。前者非空时全部新买/补买关闭；前者空且某证券的后者非空时只禁该证券。执行器只消费该裁决及正常合法性/资金检查，不添加“存在任何风险段就全局禁买”的隐含规则。

| 情形 | 作用范围 |
|---|---|
| 任一活动`SINGLE_REDUCE / INDUSTRY_REDUCE / TOTAL_REDUCE / EMERGENCY_EXIT` | 全局禁买；各自向目标而非触发线闭合 |
| `EXITING / RETIRED`、已确认资不抵债 | 全局禁买 |
| 不可靠权益、未知行业持仓、共享现金差异、未确认委托状态、池/包不健康等已定义账户或批次阻断 | 全局禁买；每个原因独立保留及解除 |
| 当前普通计划资本版本失效、FLAT_SCORE | 关闭该批全部普通买入/补买；不阻断有依据的卖出 |
| `SECURITY_EXIT`、本批已卖证券、个别数据未知的HOLD_NO_ADD | 只禁止相应证券买入；不因名称中有“风险”而扩展到无关证券 |
| 风险退出受阻剩余市值合计≥10%E | 另加全局原因`BLOCKED_EXIT_EXPOSURE` |

受阻市值按应风险退出而当前确实不能执行的**剩余**股数计量，证券去重；<10%E只消除该原因，不消除其他活动纠偏。不能把旧意图已计划卖出的全部金额或同股多个原因重复计入。

固定反例：E=100000，一只价值2000元的ST股停牌、没有未知在途订单、普通卖出已完成而有真实空槽及资金，且无其他全局限制：只禁该ST股，可对固定名单中的其他证券生成合法买单。五只各2%受阻合计10%时全局禁买；只有2%受阻但同时存在TOTAL_REDUCE时也全局禁买。风控触发、最终意图和订单生成须共同覆盖这三例。

### 8.4 合并优先级与最终意图

固定顺序：应急全退 → 个股确定退出 → 单股超限 → 行业 → 总暴露 → 普通退出/调权 → 普通买入。

每只最终剩余股数上限取所有有效卖出约束的最小值；等价卖量取最大必要值，不求和。原本不卖的股票不能因四舍五入被变成买。证券已出现在风险卖出目标中，进入本批禁买集合。

风险首次基础允许时刻在触发时即确定：即使因串行占用或报价缺失不能立即发单，也不能推迟S2/S3计时。任一批真实账户更新后再次裁决：风险已自然满足，结束对应目标并按D09.4取消不再必要的在途卖单；其他约束仍要求同一剩余卖量时保留。风险未完成，不用普通高分恢复仓位。卖量始终≤D07.3的free_sell，未来T+1释放不能提前消费；券商已扣的冻结不再扣第二次。

### 8.5 运行状态机

- `WAITING_START`：固定起点/真实首次计划检查。已知不适配不启动；未知不伪造成功。
- `NORMAL`：可生成正常周度计划，随时处理风险。
- `RESTRICTED`：有非应急全局限制。取消冲突买入，允许有依据卖出及核账。全部原因消除后恢复NORMAL，但不能重建过期计划。
- `EXITING`：25%真实触发后只撤买、卖出、核账/公司行动；状态不因E回升清除。
- `RETIRED`：正常可处置主动仓清空，未结委托都已确定。可保留不能正常交易的残余权益；继续估值、税费和回收至D。

原始真实触发布尔`retirement_triggered`永久保留，与当时是否仍有残仓无关。误触发纠正须带事实修复、复验和人工决定；已经真实发生的交易不倒删。研究修复可从事件前重放，但必须另留修复前记录。

### 8.6 规则矛盾的处理

若所有可卖部分卖完仍因冻结/残余、费用或行业限制无法达到目标，**保留受限/退出，报告不可达，不创建虚拟现金或自动加杠杆**。30只、等权、60%目标均不能覆盖真实持仓与交易事实。E≤0记风险失败和资不抵债事件，停增；不要计算正比率或把负E改成小正数。

## D09. 限价、窗口与委托生命周期

### 9.1 执行前置条件

每次实际报单均检查：有效窗口；当前资本修订号；已核验权限；证券归属；有确认报价及法定申报限制；自己的与券商的现金；未结订单；日容量；风险最终意图。执行器只接受`FinalIntent`，不得接收裸股票列表直接买入。

常规批次先卖后买。同一策略批次可以同时存在多只证券的委托，但每证券每方向最多一张未结束委托；“策略串行”不要求30只证券每只串行等待60秒。资源按固定顺序预留后才发各单。卖出阶段所有计划卖单必须已经终态，或者该证券已明确被合法性/容量/重试次数阻断；只有没有未知在途卖单时才进入买入阶段。普通卖出或低于10%的个股SECURITY_EXIT被阻断，不因此全局停买；其实际仓、资金和名额仍计入。进入买入阶段必须使用D08.3的两级禁买裁决：全局集合为空、目标证券不在证券禁买集合，并逐项通过现金、槽位、费用、容量等约束。不得再检查`any(active_risk_episode)`来替代该裁决。

窗口内新风险到来，先重新裁决两级限制；全局原因取消全部冲突买单，证券级原因只取消相应证券买单。未确认的冲突委托按在途/未知规则继续占用，不凭计划已撤销进入下一步；随后按当前真实持仓卖出。10:30后不能新增普通或风险委托，只能撤销/查询已存在订单；风险目标延续下一窗口。

### 9.2 有界限价算法

在证券本窗口首次具备执行资格且获得有效报价时，固定`anchor=last_price`。该锚只属于价格保护，不影响因子名单。买方保护上界为`ceil_tick(anchor×1.003)`，卖方保护下界为`floor_tick(anchor×0.997)`，再与当日涨跌停及生效价格笼子相交。名义30bp向外对齐tick，真实保护幅度最多额外一个tick；不能同时把买上界向下取整、HIGH成交价向上取整，制造同参考价下必然无法成交的舍入冲突。实际法定上界优先，不能因对齐而突破。

实时委托：买入用当前卖一价向上对齐tick，且不高于保护上界；卖出用当前买一价向下对齐tick，且不低于保护下界。没有有效对手盘、报价过期或不在保护范围，本次不报单。重试只刷新报价与实际数量，锚和保护边界不扩大。

研究BASE/HIGH滑点与真实限价保护是不同概念：实际券商成交按真实价格入账，不另外再扣一份模拟滑点。分钟回放如何使用滑点见D17，不能把真实手续费和模拟价差重复扣。

### 9.3 订单事实、状态与资源转移

唯一状态为`CREATED / RESERVED / SENT_UNKNOWN / ACKED / PARTIAL / CANCEL_PENDING / FILLED / CANCELED / REJECTED / RECONCILE_REQUIRED`。状态图不作为省略直接转移的依据。每笔订单保留不可改写的提交身份/原数量/限价，另保存已核实逐笔成交集合、累计数量金额、计提和已付费用、最新可判新旧的券商终态证据、撤销请求及资源。

`q`为原申报量，`f`为已核实且已记账累计成交量，`r=q−f`。真实成交按稳定trade_key只记一次；费用按同order累计差额记一次。ACK和终态数量只用于确认/对账，不第二次生成成交。全成以已核实的逐笔/确定差额成交累计达到q为准，不要求先收ACK或撤销确认。

每行中的“重裁决”表示：先原子提交真实成交/费用/资源，再用新账户修订及当前有效事实计算剩余目标；不是重发原数量。

| 当前状态 | 输入及条件 | 新状态 | 股数/现金/费用 | 剩余预约与下一动作 |
|---|---|---|---|---|
| CREATED | 本地批准、资源检查成功 | RESERVED | 不变 | 锁定现金或卖股、容量及槽位；尚未调用券商 |
| CREATED/RESERVED且尚未提交 | 计划失效/本地取消 | CANCELED | 不变，0费用 | 可证明未提交时直接释放本地预约；不发券商撤单 |
| RESERVED | 已记录提交尝试，但尚无确认 | SENT_UNKNOWN | 不变 | 全部预约保留；禁止猜测“没ACK就是没报出” |
| SENT_UNKNOWN | 可唯一关联该尝试的受理确认 | ACKED（f=0）或PARTIAL（f>0） | 不变 | 只绑定券商ID，不改变数量与费用 |
| SENT_UNKNOWN/ACKED/PARTIAL | 已核实新成交d，0<d≤r | PARTIAL（f+d<q）或FILLED（=q） | 按d真实记股数/现金、增量费用 | 部分转已用，剩余继续保留；全成时未成预约为0并重裁决；允许ACKED直接FILLED、成交先于ACK |
| SENT_UNKNOWN/ACKED/PARTIAL | 有效撤销请求发出 | CANCEL_PENDING | 不变 | 预约不释放；持久记录取消原因和请求ID |
| CANCEL_PENDING | 又有新成交d | 未全成仍CANCEL_PENDING；全成则FILLED | 真实记d及累计差额费用 | f=q即释放未成预约，取消需求自然完成；无需继续等“撤单成功”才能结束 |
| CANCEL_PENDING | 明确撤单失败且证明原单仍活动 | ACKED（f=0）或PARTIAL（f>0） | 不变 | 原预约保留，`cancel_required`仍为真；查询核对，下一新确认修订上可再输出一次取消动作；禁止新同向单 |
| CANCEL_PENDING | 撤单失败但无法判断原单是否仍活动 | RECONCILE_REQUIRED | 已确认成交照实保留 | 保留最大可能剩余预约，查询/人工核查，不按失败推断取消完成 |
| 任一已提交非闭合状态 | 券商CANCELED证据累计量/额与已记成交一致 | CANCELED（f<q）或FILLED（f=q） | 不因终态再记成交/费用 | 释放明确未成部分；实际持仓和已发生费用继续；重裁决后才允许合法重试 |
| 任一已提交状态 | 券商FILLED/CANCELED累计量>已记f | RECONCILE_REQUIRED | 不把累计量再当新成交 | 补查询逐笔或已核验的累计差额；未解释部分仍占用。补齐后由同一终态证据归约为FILLED/CANCELED |
| SENT_UNKNOWN/ACKED | 明确零成交拒单，且无相反成交证据 | REJECTED | 0新增成交/费用 | 释放预约，是否再次下单按仍有效目标和次数上限判定 |
| 任一状态 | 同trade_key、相同不可变内容的重复成交；或同控制事件ID相同内容 | 状态不回退 | 完全幂等，无新增费用 | 不重复释放、不重发 |
| PARTIAL/FILLED/CANCELED | 迟到的相容ACK或有明确较老版本的状态 | 保持当前推导状态 | 不变 | 保存观察记录，不复活订单；不能仅以received_at较晚认定内容较新 |
| FILLED | 相容的迟到“撤销结果/终态”且累计=q | FILLED | 不变 | 未成预约保持0，不重新进入CANCEL_PENDING |
| CANCELED/REJECTED/FILLED | 新真实成交、终态与现有已确认记录矛盾，且不能证明只是旧版本 | RECONCILE_REQUIRED | 可信成交仍记一次，不删除已有暴露 | 查询权威最终累计/更正证据；未能定解不重试。f=q时未成预约仍为0，不凭冲突创造可再成交数量 |
| RECONCILE_REQUIRED | 已取得足以唯一解释逐笔和终态的证据 | 按上表归约，非任意手填状态 | 只记尚未入账事实及费用差额 | 对齐后按真实未成量释放或继续预约，再重裁决 |

资金/容量/名额不共用一个“已释放”标志：买单剩余现金预约按未成量×限价＋剩余增量费；卖单剩余股数预约为可能继续成交的股数；容量为该股当日已成交金额加未成金额上界。终态只释放未成预约，已用容量当日不回滚，实际持仓仍占槽。全成与部分取消后的费用结算仍可能未结束，已计未付负债单独保留，不以订单终态清零。

归约优先级是：不可变真实成交集合 → 经核验的最新终态 → 活动撤销请求 → 受理/提交事实。累计不得超过原量；若券商确认的真实成交确实超出本地订单或保护范围，保留真实账务并记录`CONFIRMED_EXECUTION_BREACH`，隔离该单，不通过扩原单q或吞成交“修复”。缺乏可比较源版本或最终累计证据的矛盾，明确停在RECONCILE_REQUIRED。

### 9.4 意图变化对已发委托的确定处理

每次收到可信报价、资本事件、成交或终态，先更新真实账户，再将所有未结订单与最新`FinalIntent/RiskDecision`比较。**比较目标需要以当前实际股数计算，不可把该单未成交卖量先扣掉，误以为风险已经自然满足。**

- `SINGLE/INDUSTRY/TOTAL_REDUCE`目标自然满足，或所有卖出约束的合并剩余需求为0：对不再需要的在途卖单设置`cancel_required=TARGET_SATISFIED`并请求取消。仍有其他独立目标需要同股卖量时按其合并需求处理。
- 合并所需卖量小于旧单未成量：取消旧单全部剩余，不原地改q；待终态及逐笔齐备后按真实剩余需求重新生成合法单。所需量≥旧单未成量且价格/期限仍有效时保留旧单，不叠加第二张同向单。
- 资本修订号变化：相应普通计划全部未结买单设置`cancel_required=CAPITAL_CHANGED`；取消确认前禁止对应新买。转资必须先满足可转资金规则；已经发生且可信的外部转资仍照实记账，不因本地计划过期拒记。原EXIT继续，原TARGET_AMOUNT卖单按当前是否仍需减持检查；不自动改成买入。
- 新全局/证券级风险禁买按D08.3取消冲突买单。FLAT_SCORE、普通期限到期等使上层买入失效时使用相同取消机制。`cancel_required`一旦发出，在该次终态前不因后来目标恢复而撤回；新需求必须等旧单闭合后重裁决。
- 尚未确认失败的取消请求不重复发；已确认失败且原单仍活动，只在新的可信账户/订单修订下输出一次后续取消动作，操作ID防重复。已知原单未结束时永不重报替代订单；本条不增加自动追价或无限新委托。

撤销等待中的竞态成交按本订单原始身份、实际价格和累计费用记账；不得倒造反向交易去抵消“本来不想成交的部分”。已发出且不再必要的卖单继续成交，记录执行偏离并重算风险；不自动回补。若最终全成，直接FILLED，不无限停在CANCEL_PENDING。

**固定链：** BUY 300股、限价10元、初始现金10000，成交100股收佣金5，申请取消后再成交200股；结果股数300、现金6995、累计佣金5、剩余现金/数量/容量预约0、已用容量3000、状态FILLED，不生成第四张或替代买单。

`FORWARD_MANUAL`中的“请求取消/查询/重试”只表示人工操作清单与导入券商确认，不包含真实自动报撤单。小型参考投影不代替最终生产状态机及适配验收。

### 9.5 期限与重试

同证券同方向每窗口最多3个实际新委托。每笔提交后最多60秒等待，未完成请求撤销；只有终态已确认且距前次提交≥60秒，才按剩余目标尝试下一笔。无合法报价/数量而没报单不算委托次数，但不延长窗口。重新委托使用新ID，重新触发最低佣金。

窗口结束普通意图`EXPIRED`，未知委托资源不释放。风险段保留经济目标，不跨日重发原数量。次日先对账，再创建新委托。实际撤销未及时生效导致窗外真实成交，照实记录为窗口偏离，不能回填10:29或丢弃。

## D10. 当日容量与预约资源

### 10.1 容量数值

`cap_i(d)=0.01 × mean(amount_i(d前20个市场日))`，整日固定，单位人民币元。不用执行当日全日成交量。确认停牌0；任一必要来源缺失时容量未知，相关新委托暂停。

`used_i = 当日全部已确认买卖成交金额之和`；`pending_i = 未结束订单可能继续成交的金额上界`；`new_max ≤ cap_i−used_i−pending_i`。

买卖不相减，撤销只释放未成交预约，已成交永远占当日额度。部分成交从pending转used，不双计也不遗漏。资本转移、订单换ID、窗口重开不重置used；下个市场日才重置。

### 10.2 “可能成交金额”不是卖出最低限价

买单最大金额=`未成交数×买入限价`。卖单可能以高于限价成交，容量预约使用已核验的当日最高合法成交价格上界；不能用卖出最低价假装它是金额上界。

没有可靠价格上界的特殊交易日，相关容量无法给出可信保证，标`CAPACITY_PRICE_BOUND_UNKNOWN`；只进行人工核查，不绕过容量规则。实际成交导致来源修订后的上限被超出时保留真实成交并限制后续，不能删除超额交易。

### 10.3 资源登记

每个订单关联一个资源对象：现金预约、可卖股数预约、新证券槽位预约、行业/总体预览、容量预约。来源未知或撤销未确认时均保留。确认零成交拒单释放全部预约；部分成交取消释放剩余，实际仓/费用留在账本。

资源是权利的限制，不是新增负债或收益。全局核对公式见D14，不能把券商已冻结金额再从其`available_cash`扣一次。

## D11. 委托级费用、税费与成本预留

### 11.1 累计计费函数

同一委托累计成交额A：

`commission(A)=0 (A=0)`；否则`round_cent(max(0.00025 A,5))`。

第k次新增费用=`commission(A_k)−commission(A_{k−1})`，不是每笔成交各扣5元。示例累计1000、3000、24000元时，增量佣金分别5、0、1元；原委托取消后重新报一笔1000元，另一委托仍扣5元。

印花税、过户费等按FeeProfile中的费率/计价基数/方向/生效日/取整粒度分别累计。已经在佣金中包含的规费不能再收。协议未填历史费率的区间输出`FEE_SCHEDULE_INCOMPLETE`，不能把今天税费铺满A0。

### 11.2 费用入账与结算

确认成交时按本运行费用合同计提应付费用并减少净资产；如果同时已经从现金实扣，则现金减少、应付归零。最终券商清算费用替代估算只记差额，不第二次完整扣费。来源未确认的费用占用不能凭0绕过购买力。

真实回放用成交价×股数算成交额；输入已有真实成交额也须按来源精度核对。不将滑点同时体现在更差价格和单独费用两次扣除。

### 11.3 预约费用

一笔部分成交委托已发生A、佣金已计g(A)，剩余可能成交金额B，额外佣金预约为`max(g(A+B)−g(A),0)`。新委托A=0。剩余印花/过户等同理计算，已计提应付款从其他储备项剔除防双扣。

只要订单仍可能成交，至少保留其最大可能新增费用。撤单请求不释放。费用小于卖出净回款时卖出可支付自身费用；若卖出税费超过回款和可用现金，标`COST_UNFUNDABLE`，不能虚构融资。

### 11.4 股息税合同

每笔登记分红权益先按其`record_date`唯一绑定历史税则（D11.4及H04.4），再使用该税则内的`tax_acquisition_date / transfer_delivery_date`判断持有期，不是固定30/365天。转让按FIFO；同日批次按已确认成交顺序和ID稳定处理。精确月/年边界以自然月日历加法计算，月底不足日用该月末日。

2015年调整后的普通个人股票示例：转让交割日在取得日加1个月以内（含边界）使用20%；超过1个月至1年含边界使用10%；超过1年0。**历史时期、特殊股份、送转税基和实际税日仍以已核验TaxProfile为准**。不把此示例回填为所有年度税则。

分红尚未卖出批次的可能补税记录为`contingent_tax_reserve`，只限制可付款现金，不在净值重复扣为已发生负债。卖出时按最终持有期限形成真实税费负债；实际清算再结转。若卖出早于派息，保留已确定税额与分红应收，派息时不得丢失补税关系。

当期税则要求派息先扣一部分时，按`initial_withholding`减少应收/现金并记录已纳税额，卖出只补差额。未知税基或未知初始批次禁止把税设为0；可以维持核账并标证据不足。

本税类规则选择字段固定`selection_date_basis=EQUITY_RECORD_DATE`，匹配`effective_from <= record_date < effective_to`及股份/分红类别；0条为TAX_RULE_MISSING，超过1条为TAX_RULE_OVERLAP，均不得猜率。登记权益保存税表Profile、selected_rule_id和rule_selection_date。税制选择日、持有期起止日、负债计提/实际扣缴日是三个独立维度：派息或卖出时不重新按其日期选税制；后来税表变化不倒改旧分红，仅明确历史纠错才重投影。真实税表生效端点须由通知及适用实施证据正规化，不能把自然语言“之后”或成文日期交给程序猜。

## D12. 唯一账本、分录及公司行动

### 12.1 守恒分录

| 事件 | 股数/现金/权益变化 |
|---|---|
| 买入b股、成交p | 股数+b；现金−bp；费用扣一次；新增股数按规则T+1可卖 |
| 卖出s股 | 股数−s、FIFO消耗批次；确认可用回款才增加可付款现金；卖出费税发生一次 |
| 预约/券商冻结/撤销确认 | 不改变净资产；只转移可用限制 |
| 股息登记 | 保存登记日真实持股权益，不立刻增加E |
| 除息 | 价格用新股基原价；现金应收+登记股数×税前每股分红；不能同时用隐含再投资增加股数 |
| 派息 | 现金+实到账；应收相应减少；税扣缴按实际条款；不是第二份盈利 |
| 送转 | 形成股份权益/增加应得股数，按上市可卖日期释放；非整数份额另记权利 |
| 配股 | 不自动认购；不增加未付款股份。权利可交易/失效/现金补偿按事件记录 |
| 资本转移 | 现金变化与基金份额变化同时发生；不是投资收益 |

交易已经入账的股数现金与券商快照差异，先找到缺失/重复事件，禁止直接把余额覆盖后继续下单。任何主动量都不能超过当前可卖，任何真实被动事件都不能为满足策略配额而丢弃。

### 12.2 股息和送转流程

事件必须有`corporate_action_id, record_date, ex_date, pay_date, share_credit_date, listing_date, ratios, cash_gross, tax_basis, source_refs`；不适用日期明确null。一个事件分阶段处理，各阶段`(action_id, phase)`只可生效一次。

登记数量按登记日收盘全部真实归属股份（含当日确认买入、排除当日已卖）记录；正常持仓和有权益的冻结仓一并计。登记日之前未知的权益不能假设为0；之后补证据从登记状态修复。

送转导致每原股变成r股时，登记应得份额按官方逐账户/逐事件取整条款处理，不能从价格跳变推r。原税批次与新增税批次的取得日是否继承、送红股是否计税，来自事件TaxProfile；不得把所有资本公积转增都当相同税务事件。

权益已经经济生效但新股尚未到账时，记录`share_receivable`及股份基础；估值不得同时按旧基础市价和完整新股权益重复计算。新股正式计入position时清相同应收。确认为可卖之前不加入sellable。

### 12.3 估值顺序

正常交易采用该时点可见的未复权价。确认停牌采用与当前股份基础一致的最近有效估值，保留原日期及`PROVISIONAL_SUSPENDED`；不能将平价停牌误当低波动证据。

发生除息/送转时，若无新价格但官方参考价或明确转换能对齐基础，则使用该有证据参考估值并标暂估；否则`UNRELIABLE`，不得直接拿旧每股价格乘新股数。

暂估不等于自动失败，也不等于自动通过。若有已知估值上下界，计算相关风险/采用可能区间；任何决定性阈值可能被跨越，输出证据不足。没有边界或终局价值依据时不推算“影响很小”。

### 12.4 残余权益

必须有已确认的终止正常交易/换股残余事件才能转`RESIDUAL`，不是“最后出现一根Bar”。暂时停牌或本次卖不出不能转残余腾槽。

转残余仅改变正常槽位计数；股数、应收、已确认估值及股票性质风险继续计入E和风险。清算前无现金到账不增加购买力；被动转换继承股票策略归属。回收确认后按真实现金/股份转换记账，旧账户和停用状态保留。

未结价值未知：保留历史过程和明确情景，不自动零估值，也不末价全额变现；采用结论按D20证据规则，不选择有利清算情景。

### 12.5 精确份额化、日终高水位与资本流

初始入金F>0时`U=ExactRatio(F), NAV=1/1, HWM=1/1`。流前可信权益E>0、份额U>0；实际外部资金流F转入为正、转出为负：

`v=E/U`；`U'=U+F/v = U×(E+F)/E`；`E'=E+F`。

以上全部以D02的精确比值执行，不经过50位Decimal除法。于是`E'/U'=E/U`为精确恒等式，而非小数误差范围内相等。转出先满足真实现金、占用、待付等限制；不得用未分配额度作为资本流。E+F<0或U'<0非法。全部赎回且无剩余权益/负债时U'=0，保留最后NAV/HWM并停止资本状态，不计算0/0，也不清除停用历史。

资本事件只改变权益及份额，不刷新正式HWM，也不提前产生新的日内DD触发。正式日终：`NAV_d=E_d/U_d; H_d=max(H_prev,NAV_d); DD_d=1−NAV_d/H_d`；用精确比值检查20%、25%和30%。E≤0另按资不抵债规则处理，不把负NAV夹成0来掩盖损失。

**循环小数边界：** 日终前E=75000、U=100000、HWM=1，实际转入1元，U'=300004/3，E'=75001，NAV仍为3/4，DD恰为1/4；随后同价值日终必须触发25%。转资时尚无正式日终，不凭此例增加盘中止损；它只证明资本流不能使应在日终出现的等号消失。

提款、连续多笔资本流、恢复后继续转资都用相同递推。NAV/HWM的展示值可以到8位，但不能恢复成计算状态。`units、nav、hwm、dd`全部按规范化ExactRatio序列化；缓存比例与从已确认资产重算的精确比例不等时必须失效重建。

**晚到会计纠正：** 实际资金流金额/时间、真实成交和当时决策是不可变事实；由它们计算出的份额、资本流前NAV、历史高水位和DD是可重建派生量。更正生效早于某资本流时，从最早受影响事件之前重新投影全部后续资本流，不把旧派生份额视作事实沿用。已发布旧净值保留为SUPERSEDED审计记录，当前有效投影唯一；不回填过去知识或倒造订单。具体固定链见H07.4。

## D13. 日志、快照、幂等与恢复

### 13.1 本地最小文件

```text
bundle.json                     # 唯一外部输入根；study和profiles按H02嵌套
facts/*.parquet                  # 已规范事实及来源记录，不是第二账本
runs/<run_id>/events.jsonl        # 该账户唯一提交事件流

reports/                         # 只读派生报告
```

文件身份用明确版本、顺序号、记录ID，不引入全量哈希校验、复杂签发或发布审批。单写者本地文件锁用于避免同一账本双写，人工批准记录用于现金串行，不是工作流平台。

### 13.2 原子事件提交

事件包含`seq, event_id, kind, occurred_at, known_at, payload, input_refs`。同一原子交易的股数、现金、应付、税批次和占用转换放在同一事件payload中；先计算和校验，单行写入并flush/fsync后才更新内存“已提交”序号。

快照包含`detail_version=V5D2, projection_revision, last_committed_seq`和精确比值字段，写临时文件后原子rename，只缓存已提交seq。恢复以日志为准，快照落后就重放；快照超前、序号断裂、内容冲突则停止增风险。崩溃截断尾行不视作已提交，可在保留原始损坏片段后截去未完整尾行；不能删除任何完整已提交事件。

### 13.3 恢复顺序

加载固定配置 → 读取最后完整事件和快照 → 查询/导入真实未结委托及成交 → 对账股数、现金、费用与占用 → 重新估值及风险裁决 → 仅继续仍在期内的意图。

精确状态恢复校验：分子分母规范、约分、NAV=精确E/U及HWM约束必须通过；旧V5D1只有舍入Decimal份额的快照不得直接改标签接入。必须由可靠初始状态及不可变事件重建为V5D2，资料不足返回`EXACT_STATE_REPLAY_REQUIRED`并禁止新增。重投影改变projection_revision时，受影响点及其后的旧快照失效；不能先采用旧units再仅补当前资产。

已过期普通意图不补报；风险按当前剩余目标重算。SENT_UNKNOWN先查询，不因本地没有ACK就重发。手工补录必须带来源和原因，不能覆盖原事件。实时不能回滚真实成交；回放修复使用新run_id并标旧结果失效。

## D14. 共享现金、串行批次与双视图对账

### 14.1 唯一归属

两套范围`ETF_set`与`STOCK_scope`启动时必须互斥。普通成交、股息与税按证券直接归属。配置违反前提则拒绝共享运行，不实现数量分摊或争议裁定。

共同现金记录保存`C_ETF, C_STOCK, C_UNASSIGNED`、资本流、资金承诺和已解释清算差异；各策略自己的股数/权益由对应视图负责。不能将全券商资产作为任一策略净值分母。ETF视图尚不具备时，使用人工确认的独立归属快照适配；能力未验收只输出计划。

### 14.2 现金两道门

策略可授权额：

`own_free = own_cash_book − own_restricted − own_outstanding_commitments − due_cash_not_reserved_elsewhere − contingent_tax_reserve`。

券商可授权额：

`broker_free = broker_confirmed_available − approved_not_yet_in_broker_freeze − due_cash_not_already_reflected`。

本批可用=`min(own_free,broker_free)`。这里`own_restricted`仅指非订单原因的已确认限制，订单冻结统一归入`own_outstanding_commitments`，两者不重叠。每个被减项目必须有唯一resource_id及`already_in_broker_available`标识；未知映射不继续批准新批次。不能对同一冻结既减broker_available又再减一次全部冻结。

账本现金包含冻结；预留只限制购买力。委托从PREAPPROVED转BROKER_FROZEN时只转状态，剩余占用不中断；部分成交转为真实股数和现金支出，剩余冻结继续。撤单确认释放未成交部分，撤单请求不释放。

### 14.3 串行批次

共同状态`IDLE → AUTHORIZED(owner,batch,amount) → EXECUTING → RECONCILING → IDLE`。任何时刻只能一个主动新委托批次。前批有未知委托或未解释现金差异不得进入IDLE。

人工批准必须依据不早于最近成交、转资和冻结变动的快照，绑定`account_revision`和金额；新事实到达后重算，不沿用旧额度。股票应急卖出可优先于尚未启动的ETF普通买入；已经发出的ETF订单需先确认/取消，不把它当不存在。

串行延迟使股票批次错过10:30时普通计划到期，风险续下一窗口；不擅自延长执行时段。无法稳定满足这项边界则外部运行验收不通过，不能因程序已实现而批准共享实盘。

### 14.4 原子现金转移

只转已确认且无占用、覆盖待付需要的现金。单条共同资本事件包含转出A、转入B和相同F，两策略视图都消费同一个transfer_id；`ΔC_A+ΔC_B=0`。在各自转资前NAV上增减units。未分配额度变化不是资本流。

任一策略普通买入计划绑定的`capital_revision`变化即失效，已发买单走D09.4取消闭合；风险按新E处理。转出不能为另一策略制造两份缓冲现金。未解释差额不能记入UNASSIGNED以强行配平。

### 14.5 对账方程与失败结果

证券按互斥归属逐项核对`总股数、可卖数、冻结数`。同一结算时刻：

`C_broker_book = C_ETF + C_STOCK + C_UNASSIGNED + 已解释时点差异`。

权益对账先把双方应收、应付、估值时点与券商展示基础对齐。可用现金不是净资产；含不同清算口径不能直接要求数值相等。

开始交易、每批结束、日终都对账。交易数量任何未解释差异必须阻断新增；金额显示舍入只允许明确精度内的0.01元项目差，实际现金差不能凭比例容忍。券商源大于本地和小于本地都须查明。必要且事实充分的卖出不因无关的另一个策略信息缺失被一概禁止，但必须有自身可靠可卖量及串行确认。

## D17. 日线代理与分钟窗口撮合

### 17.1 共用投资规则，不共用不存在的市场信息

因子名单、固定金额、风险优先级、股数现金、费用及停用规则共用。执行器的报价与成交事实来自明确模式；同一报告不得拼接更有利的模式。

### 17.2 日线开盘代理的确定过程

执行参考时刻记为当日09:30，普通名单只来自既有截止；进入该次代理的风险/状态/公司行动只允许在09:30前可得。09:30开盘值只作该次执行价、数量与可行性估计，不倒流到选股或源选择。

每个代理执行日只作一轮：风险及普通卖出按优先级，以实际已模拟成交回款处理固定买入；价格分别为原始开盘乘`1±slippage`再按方向不利取整，且必须满足有效申报保护和法定边界。开盘停牌/价格不可用、买在涨停或卖在跌停均不填成交；不使用当日高低价或全日成交量来判早盘成交。

当日累计容量只用执行前20日数据。代理阶段不虚构三次盘中追单或虚构盘口部分量；无其他已知限制时按一次合法目标量模拟，否则0。这是已标记的日线成交假设，不是现实全额成交认证。卖出回款与后续买入同代理价格也只作为诊断简化。

窗口参数10:00—10:30仍用于目标的真实操作合同；日线09:30代理报告必须显式标`NOT_WINDOW_CERTIFIED`，不能将10:00才取得的事实放入09:30。下午新风险在下一代理时点处理，不能回填当天开盘。

### 17.3 分钟窗口的确定撮合

分钟Bar规范为`[bar_start,bar_end)`且仅在bar_end后可供决策读取。下单只能使用此前已完成Bar/已观察报价，不使用当前Bar最终高低价、量额。

无真实盘口的研究分钟模式：只在整分钟边界行动，使用上一完成Bar收盘作为锚及参考价，限价取D09固定保护边界；这是显式分钟报价代理，不套用实时tick的3秒新鲜度要求。

在10:00用截至10:00刚完成的上一Bar作决策并提交，首次可成交区间为[10:00,10:01)，不得使用该区间开盘/高低/量额决定刚才的订单。成交发生标为该区间内的模拟事件、结果直到10:01才可见；卖出回款到10:01才可用于下一买单。非整分钟到达的信息在下一整分钟行动，不倒插委托。10:29提交可以尝试[10:29,10:30)；10:30只能收确认、撤单，不能新报。

同一10:01时点先处理刚结束Bar内已有委托的成交，再处理60秒到期撤单。禁止设计成订单10:00提交、10:01先撤掉、10:02才首次允许成交的自相矛盾时序。

单Bar候选成交价=`该Bar原始开盘×(1±滑点)`，按买高卖低取整；必须同时在该Bar已实现价格范围、订单限价、法定范围内，且真实交易状态非阻断。使用Bar事后高低价只用于已下订单的结果检查，不用于下单。价外则该Bar不成交，不能把代理价夹回有利边界来保证成交。

该Bar成交量最多为剩余委托量、剩余日容量允许股数和该Bar已实现成交股数三者之小；不能生成超过市场实际量的成交。成交数量可非整手；委托数量仍必须合法。没有盘口队列证据，因此即使满足也只是固定代理假设，报告不能声称真实排队保证。

一笔60秒未完成的订单请求撤销，按该模式已知终态释放后才可下一次委托，最多3次。风险触发、资金转移、卖出回报和买入发生按事件序处理；在用分钟表内没有完整窗口覆盖的会话不可默认为全额成交。

### 17.4 模拟价格与费用的唯一处理

研究滑点体现在上述代理成交价格，佣金/税按该代理成交额计算；不再次计现金滑点费。真实回报模式使用真实成交价格，只做实际费用核对，另将滑点作为报告统计，不扣第二次。

窗口内长期发生价格代理无法成交不是数据错误，保留它对持仓、现金和采用的影响。代理模式不能自动切换另一价格让策略完成。数据不够时限制证据，不扩大成全市场逐笔平台。

## D18. S0—S3的因果压力时钟

### 18.1 基础允许时点

`first_window_after(t)`：若在交易日10:00之前，返回该日10:00；在[10:00,10:30)内，返回不早于t的下一引擎可行动时点；10:30及之后或非交易日，返回下一市场日10:00。普通批次基于周度截止计算。日线代理另按不早于信息可见的下一09:30代理时点映射，不混用10点信息。

### 18.2 情景规则

- **S0**：基础允许时钟，BASE滑点。
- **S1**：同一事件与时钟，HIGH滑点。
- **S2**：每个普通批次、每段独立风险目标第一次允许执行整体移后一个市场交易日，保留钟点；普通整窗口有效期随移。风险随后重计划不再次加一天；新信息仍按真实时间取消买入或更严风险覆盖。独立风险覆盖普通意图后，普通批次的到期不得消除风险段；已被风险禁止的普通买入也不因S2延后重新有效。
- **S3**：HIGH；每风险段以首次基础允许交易日为d0，d0、d1、d2三日禁止作用范围股票卖出，d3才恢复可尝试。已真正停牌/跌停仍继续不成交，不能保证第四日卖掉。

S2/S3分别回放，不叠加；日内可用报价/现金不随意提前。名额、资金、费用、公司行动及净值照常流转。

### 18.3 作用范围与重叠

个股段作用于该股；行业段作用于对应行业股票；总暴露和应急段作用于本股票策略全部股票。段启动时记录成员，此后三日其作用范围覆盖原成员与同范围新被动获得成员，防止改分类/换股代码绕过。ETF资产不被自动纳入股票段。

限制作用于范围内**所有卖出意图**，包括普通退出，不能借普通订单绕过应急阻断。重叠风险段取其阻断集合并集；每段保留自身计时，日常重算不重启三日。一个独立新段合法触发可以有自己的三日，不以此覆盖旧段起点。

风险目标自然满足后不强制卖出；已启动三日市场受阻记录在其期限内仍适用于任何后来确实需要的范围内卖出，不凭结束风险段删除市场冲击。段结束后同类型再次跨触发线为新段；应急段没有自动新起点。

### 18.4 终点评价

所有情景保留风险识别至首窗口、串行协调、S2延迟、S3阻断和后续真实失败的损益。退出指令不增加现金。到D仍有残仓按D时已知估值记账，列出未完成原因；未知估值决定资格则证据不足。不能在D强制末价变现，也不将停用日作为绩效终点。

## D19. 指标、全期绩效与运行可用性

NAV、HWM、DD及MDD保存为ExactRatio，峰谷和风险门槛由精确比较确定；年化幂运算、波动等展示/排序指标按本节Decimal/统计约定计算，不反向写入风险状态。

### 19.1 日终序列

每个已启动单元从入金NAV=1至共同D的每个市场日保留净值。停用/空仓期继续，现金不自动投入其他资产；研究现金收益默认为0，实际确认利息在真实模式按归属记录。收益率`r_d=NAV_d/NAV_(d−1)−1`。

最大回撤`max_d(1−NAV_d/max_{s≤d}NAV_s)`，不四舍五入参与资格。日终预警/应急严格用这条同源净值。峰值日期取最早达到该高点的日期；谷值取首次最大回撤日期；恢复为之后首次NAV≥峰值，未恢复记录截至D的持续长度与未恢复标记。

### 19.2 年化、费用与换手

`Y=(D的日终时刻−入金时刻)/365.2425天`，`CAGR=(NAV_D/NAV_0)^(1/Y)−1`。Y≤0为不足，NAV≤0时不输出常规复利年化并记录破产/风险失败。不能用固定252或盈利天数年化。

年度收益按上一年末NAV链接，第一年用入金NAV，不能丢首日费用。波动可按实际市场日收益样本标准差×sqrt(当期平均每年市场会话数)列观察值，不影响V5采用硬条件。

换手固定为每次成交`|amount|/(2×成交前一致权益)`的累积，按年除Y；另列买额、卖额、成交笔数和委托笔数。资金流前后分别用对应权益，不拿未来注资后的E稀释过去交易。费用金额按真实计提汇总，年费用率=`Σ费用/期间时间加权平均E/Y`，与CAGR减少量不是同一指标。时间加权平均E按连续两条已完成权益记录间以前一条E作分段常数积分除以总自然秒数；资本事件前后分别记录并切分区间，休市期间沿用上一权益，不使用未来权益回填。

### 19.3 运行持续性输出

每单元输出`start_pass, first_execution, retirement_triggered, retirement_trigger_at, retired_at, operating_days, normal/limited_days, healthy_week_ratio, max_bad_coverage_streak, uncertain_weeks, average_stock_ratio, average_names, end_residuals`。

`operating_days`为启动至应急触发前或D的市场日数，`in_market_fraction`为实际持有正常股票市场日/完整观察市场日数。停用后现金期不用于美化“正常运行率”。覆盖评价仍按D05保留完整应评估周。

### 19.4 对照解释

B0使用相同经济池、风险、费用与现金，但不要求因子覆盖；B1/B2才适用包联合有效集。共同评分集规模归因是报告诊断，不产生替代正式净值。行业/市值暴露报告至少包括市值几何均值、中位数、池内分位、行业权重与未知部分；不凭回归残差自动宣称最终组合中性。

外部ETF对象由StudyDefinition在看结果前指定，含实际上市日、数据口径、费用、现金配置和共同比较窗口。未指定时不得替用户挑表现较差的基准；经济比较状态未完成。指数长历史可作情景，不假造上市前ETF交易。

## D20. 采用资格、排序和停用后的重新申请

### 20.1 逐金额配置裁决

每个`(V5D2, package, capital, permission, execution_profile)`单独收集四起点四情景。已知硬失败与证据不足均保留；不能只输出第一个原因导致其他问题消失。

顺序：

1. **真实性**：来源/时点/唯一账本/决定性估值不通过或无法证明，不能入采用名单。
2. **可运行性**：四起点首次适配通过；正常S0/S1的覆盖≥95%且无连续3周不足；共享现金、实际执行能力满足。已知不适配为REJECTED，事实未知为INSUFFICIENT。
3. **存续**：任何起点S0—S3真实触发25%应急，配置REJECTED，不等完全清仓，不被其他幸存单元覆盖。
4. **风险**：16个单元全期MDD≤30%；停用与回撤失败可同时记录。
5. **经济性**：前四项通过后，稳健年化=`min(A0…A3的S0,S1 CAGR)`，须>0。S2/S3不进入此年化排序，但仍是硬资格。排序按稳健年化降序、16格最坏MDD升序、四起点S0/S1最大年费用率升序、因子数量升序；仍相同按包ID稳定排序，不冒称细微差距有统计显著性。

测试包始终ENGINEERING_ONLY。日线代理无论收益多好，部署证据仍不足；不得自动变为REVIEWABLE。实际权限/费用改变后该金额配置重放。

### 20.2 与B0的增量和人工投资取舍

当B0同金额配置硬资格也通过时：A0的BASE、HIGH中B1年化均不低于B0，且至少一格年化更高、最大回撤更低或交易负担更低，可以给出明确增量推荐标记；仍须完成ETF替代比较和用户授权。交易负担比较使用D19同口径年费用率/金额换手。

若收益降低而风险改善等相互取舍，标`TRADEOFF_PENDING`并展示差值，不让代码临时更换目标函数。B0停用而B1存续，只能记完整方案运行改善，不据此认证纯因子预测能力。B2只有缓冲对照角色，不自动取代主候选B1成为冠军。

### 20.3 停用正收益反例

十年净值1→2→1.5后现金持有，CAGR约4.13797%、MDD25%，其绩效计算可以正确。但`retirement_triggered=true`使它在收益排序前被否决，不能战胜持续运行3%的可用配置。

真实停用后新入金、改名字、换有利起点均不恢复。重新申请必须为有实质变化的新配置或有证明的错误修复，回放原固定矩阵、验证受影响外部事实并取得用户新授权。旧实际损失不删除。

### 20.4 数据错误与策略失败分离

模拟器错误/数据错误：修复后以相同经济规则重放，旧结果失效但不算发现新alpha。经济规则本身失败：保持REJECTED，不自动改60%、25%、起点、费用或尾部处理。全部候选失败时返回`NO_ADOPTABLE_CONFIGURATION`。

未通过基础输入的全现金路径不能作为低风险赢家；缺少规定起点、未知费用、未对齐QMT主源等不能被研究排序掩盖。

# 小市值周频策略｜接口与输入契约 V5D2

**本文件是《01_详细设计》的组成部分，不是另一套策略。** 它固定字段、枚举、调用次序和外部输入缺失时的行为。配套`inputs/bundle.schema.json`负责结构校验，正文的跨字段与业务校验仍必须实现。

## H01. 字段与序列化规则

### 1.1 基本类型

| 类型 | 唯一表示 | 校验 |
|---|---|---|
| 金额/价格/固定比率参数 | JSON十进制字符串，例如`"100000.00"`、`"0.60"` | 按D02从有限十进制精确转换；实结到分与展示计算才在合同位置舍入 |
| 股数 | JSON整数 | 计划非负；事件用`side`表达方向，不用负申报量 |
| ExactRatio：排名、units、NAV/HWM/DD、硬比例 | `{"num":"-1","den":"4"}`，分子分母均为十进制整数字符串 | 任意精度、约分、den>0；零为0/1，禁前导零/负零/浮点；比较交叉乘 |
| 时间 | ISO8601含时区，例如`2026-10-16T20:00:00+08:00` | 内部UTC；市场日期取Asia/Shanghai，禁无时区 |
| 日期 | `YYYY-MM-DD` | 必须是合法自然日；交易日另查日历 |
| 证券 | 稳定`security_id`＋当时`trade_code`＋`exchange` | 代码更改通过有效区间映射；不得让今天代码替代历史身份 |
| 空值 | JSON null | 只表示明确不适用/待补；必须同时有status/reason，不能作0 |
| ID | 可读固定前缀＋父对象ID＋单调序号 | 不依赖市场收益，不使用全量源码哈希；重新尝试订单用新序号 |

ID在本研究目录和账户内唯一即可。示例：`study-001/A1/S3/500000/B1`、`run-001/plan-0042`、`plan-0042/ord-0003`。实际证券成交ID以券商稳定键为准，不生成伪成交ID消重。

### 1.2 外部资料状态

`NOT_PROVIDED`：缺资料；`DECLARED`：已经给出但未核验；`SAMPLE_CHECKED`：仅明确样本；`VERIFIED_FOR_SCOPE`：已经核对所声明范围。状态不表示盈利或交易授权。

每个Profile必须有`profile_id, status, scope, source_refs, payload`。`scope`至少写用途、市场、日期和账户/数据范围。未提供时payload=null；不得把空payload配成已验证。样本通过不能自动扩大scope。

### 1.3 Result

```text
Result:
  status: OK | PARTIAL | UNKNOWN | INVALID | NOT_APPLICABLE
  value: 对应对象或null
  reasons: [{code, scope_type, scope_id, message, input_refs}]
  produced_at: 审计生成时刻，不用于历史选股
  effective_asof: 本次计算允许看到事实的截止
  input_revision: 本次消费的账户/事实版本
```

`status=OK`也不等于投资通过。`PARTIAL`只能交给明确接受部分资料的消费者；普通下单入口不能把部分账户当完整账户使用。异常值不得通过`get(...,0)`消失。

## H02. 一次研究需要的固定输入

### 2.1 唯一输入Bundle及StudyDefinition派生

只有`inputs/bundle.schema.json`规定的Bundle是外部输入：`bundle_version、baseline、execution_technical、study、profiles`。不接受扁平Study输入或旧枚举别名，不设置自动兼容层。

`bundle.study`必填且仅允许：`study_id, detail_version, end_date, capital_mode, capitals, start_years, roles, scenarios, execution_mode, fact_snapshot_id, purpose`。空的外部事实可用Schema许可的null表达，随后业务层明确阻断。`execution_mode`唯一序列化值为`REPLAY_DAILY_PROXY / REPLAY_MINUTE_WINDOW / FORWARD_MANUAL`；`DAILY_PROXY/MINUTE_WINDOW`不是可输入别名。

加载先校验整个Bundle，再由纯函数`normalize_study(bundle)`一次生成内部`StudyDefinition`。内部对象是派生视图，不额外接受一份用户可编辑的JSON：

| 内部字段 | 唯一来源 |
|---|---|
| study的全部基础字段 | `bundle.study`同名字段原值 |
| `source_profile_id` | `bundle.profiles.sources.profile_id` |
| `universe_profile_id` | `bundle.profiles.universe.profile_id` |
| `rulebook_profile_id` / `rulebook_id` | rules外壳profile_id / `rules.payload.rulebook_id`，payload=null时后者null |
| `fee_profile_id` | fees外壳profile_id；有payload时其中fee_profile_id必须与外壳相等 |
| `factor_profile_id` / `factor_package_id` | factor外壳profile_id / `factor.payload.package_id`，缺payload时后者null |
| `bootstrap_profile_id` / `bootstrap_id` | bootstrap外壳profile_id / payload.bootstrap_id（可空） |
| `benchmark_profile_id` / `benchmark_definition` | benchmark外壳profile_id / payload（可空且沿用外壳状态） |
| `baseline` / `execution_technical` | Bundle同名固定对象的只读引用，禁止复制后修改 |

source payload中的`source_profile_id`也须与source外壳一致。其余领域ID（如universe_id、rulebook_id、package_id）与Profile ID是不同命名空间，不要求字面相等，但只能从对应payload取得。任何存在的重复引用须指向该Bundle唯一对应对象；不存在、冲突或伪造的引用返回PROFILE_REFERENCE_MISMATCH。所有Settlement/Fee/Factor依赖引用仍按其对象合同逐项核对，不由此自动通过外部能力。

不允许在`bundle.study`加source_profile_id、fee_profile_id等派生字段；additionalProperties=false保持。恢复时固定的规范StudyDefinition若与从已绑定Bundle重建的结果不同，拒绝继续该run。Profile缺失仍能生成带外部不足状态的工程视图，不能通过补一个假ID获得投资资格。

固定矩阵为B0/B1/B2、四起点、四情景；DEFAULT_TWO金额字符串为`["100000","500000"]`，实际金额ACTUAL_ONE独立检验。`DEPLOYMENT_CANDIDATE`只是评价用途，不授权交易。缺D或起点所需数据保留不足单元，不删格；B0不用因子覆盖筛经济池。

### 2.2 基线配置校验

固定常量全部由V5D2常量表提供；输入中的副本只作显式记录，必须与基线相等。可填写外部事实，不可在命令行临时把60%改70%。拒绝未知键，防止错误拼写被忽略。

执行技术配置本版固定：tick向外对齐的30bp保护、3次委托上限、60秒等待/重试间隔、tick报价3秒、账户5秒。修改须建立有记录的详细配置修订和受影响测试，不由编码者为获得成交率而调参；不回写V5的固定投资参数。

### 2.3 UniverseProfile

必填：ETF允许证券集合、股票允许市场/板块、历史非金融分类标识、板块权限及核对范围。股票普通范围SH/SZ非金融普通A股；禁止以ETF的证券分类映射替代。

证券互斥在启动和被动换股后校验。某板块权限UNKNOWN就不买该板块；不能先在含该板块宽池跑赢家，再剪去无权限股票而继承原结果。

历史证券主表至少有`security_id, trade_code, exchange, board, valid_from/to, list_date, trading_end_date, legal_end_date, source_ref`。`trading_end_date`只在当时已公开事实或事后账户生命周期核账中使用，不能提前作预测过滤。状态区间左闭右开，不存在的结束日期不能擅自填成今天。

## H03. 因子包接口：公式待补，行为不能待补

### 3.1 FactorPackage

```text
package_id, version, purpose(TEST_ONLY/INVESTMENT_CANDIDATE), factors:[FactorSpec]
aggregation=EQUAL_WEIGHT
preprocessing=AVERAGE_TIE_PERCENTILE_MINUS1_PLUS1
joint_rule=ALL_FACTORS_VALID
neutralization=NONE
```

空因子包非法，重复factor_id非法。K为实际登记项数；不得为了保持旧五组结构补假因子。包通常2—3项，但超过3不由程序悄悄截断；必须是事前登记的固定包。

### 3.2 FactorSpec

| 字段 | 内容 |
|---|---|
| `factor_id / implementation_id` | 稳定公式号与已登记纯函数名；禁止eval输入公式 |
| `direction` | HIGHER_BETTER / LOWER_BETTER，恰好应用一次 |
| `inputs` | 字段、单位、报表合并口径、期间、滚动窗口及依赖时点 |
| `output_unit / output_quantum` | 输出单位与显式数值量化，避免浮点并列不稳定 |
| `validity_rules` | 分母、非有限值、必要期间、可比性、最小有效样本 |
| `freshness` | 报告期最大自然月≤15；价格窗口不得缩短或用未来填充 |
| `golden_examples` | 输入、确切输出/原因码；含负数、缺失、修订与未来追加 |
| `sources_scope` | 当前可提供字段和历史语义，不仅是接口名 |

公共层不推断“ROA到底用归母净利润还是合并净利润”。未给具体公式的因子实现返回`FACTOR_IMPLEMENTATION_MISSING`，可用TEST_ONLY夹具继续其他模块。投资包采用前必须提供公式号和以上全部内容。

新增因子不得读取账户余额、交易结果、未来收益或当时尚不存在的证券分类；不允许自动选择方向或近期最佳窗口。更换包形成新的研究配置，并重新做联合覆盖、完整账户及采用评价。

### 3.3 FactorValue状态

`VALID`：数学与经济解释成立、时点有效；`MODEL_INAPPLICABLE`：已确认分母非法、期间不可比等；`STALE`：已过明确有效期；`SOURCE_UNKNOWN`：未能确认来源；`SOURCE_CONFLICT`：未解决冲突。

只有VALID进入J。健康周中MODEL_INAPPLICABLE/STALE触发普通退出；UNKNOWN/CONFLICT走两健康周规则。合法负利润是VALID，不因数值负而划入模型不适用。

## H04. 日期规则、费用与清算输入

### 4.1 TradeRule行

```text
rule_id, market, board, security_scope, effective_from, effective_to,
public_at, evidence_ref, verification_scope,
price_tick,
buy_min, buy_step, sell_min, sell_step, allow_full_odd_exit, max_order_quantity,
limit_method(EXCHANGE_BOUNDS/PERCENT_REFERENCE/NONE),
limit_up/down或limit_percent及除权参考价字段、取整规则,
intraday_band_method, settlement_id, marketcap_floor或NOT_APPLICABLE
```

NONE与NOT_APPLICABLE都是已经确认“不适用”，不能表示没查到。对公式型价格限制按当期规则的参考价和tick舍入执行。公式方法从固定代码登记表读取，不接收自由脚本。未识别的新规则返回RULE_UNSUPPORTED，不调用宽松默认分支。

### 4.2 SettlementRule

明确以下相互独立的时间，不用一个“T+1”字段包办：

- 买入股份经济确认时刻：真实成交确认；可卖释放的市场日/时刻。
- 卖出现金交易可用时刻，与可转出/可提现时刻。
- 送转/换股应收成为已到账股份时刻，新增股份可卖时刻。
- 税务取得日和转让交割日如何从券商事件映射。
- 手续费、税费何时计提，何时从券商现金实扣。

标准账本`cash_book`表示已经确认归属的证券资金记账额，不等同可提现银行余额。确认卖出即按该清算合同增加对应现金资金余额；未到可交易时刻的部分同时形成非订单限制。若所用券商合同明确先记应收再转现金，则采用其固定`PROCEEDS_RECEIVABLE`模式，金额只在应收或现金一处出现；同一Fee/SettlementProfile内禁止临时切换。两种映射的标准E和交易可用时刻必须一致。

**研究基线使用`TRADE_CASH_BOOK`：** 卖出成交确认入cash_book，并按结算规则限制可交易/可转出时间。实际券商若需应收映射，由适配器先转为同一标准事件，不让账户核心维持第二模式。未知清算时点不能默认可用回款。

### 4.3 FeeRule行

必填：`fee_id, fee_kind, effective_from/to, market, side, base_kind, rate, minimum, maximum_or_null, included_in_commission, charge_unit, rounding, settlement_id, source_ref`。

`charge_unit`只允许ORDER_CUMULATIVE、FILL、ACCOUNT_DAY、ENTITLEMENT中的已实现类型。佣金固定ORDER_CUMULATIVE；税与其他法定费按真实取整粒度提供，不强行全部改成按成交。跨日期重新委托是新order；同order各次成交费累计减已计提，不能覆盖或重复扣。

最终费用对账必须有`assessed_fee, already_accrued, already_paid, settlement_cash_change`：净值本次变化仅`assessed_fee−already_accrued`，现金按真实结算变化，应付结余等于已评未付。多退少补照实处理。

### 4.4 TaxProfile与FIFO算法

**规则选择日固定为股权登记日。** `DividendTaxRule.selection_date_basis`为必填常量`EQUITY_RECORD_DATE`，其他值包括PAY_DATE、SELL_DATE均非法。`effective_from/to`是已经核验、正规化的登记日适用区间，统一左闭右开；不是政策发布日期或券商实扣日。按`security_class、dividend_type`精确匹配类别，再用`from <= record_date < to`筛选：恰一行绑定；0行TAX_RULE_MISSING、多行TAX_RULE_OVERLAP。未验证的历史端点保持外部缺口，不从自由文本猜生效等号。

对每次分红先绑定`tax_profile_id、selected_rule_id、rule_selection_date=record_date、selection_date_basis`；转让时只在这个税制的tiers中按`acquisition_tax_date`到`transfer_delivery_date`分档，不按卖出日期重新挑今天税表。规则ID相同而内容变化必须走明确历史纠错与重投影；不能静默覆盖已登记税务绑定。

选择税制、持有期分档、确认负债、实际支付分开：登记只保存权益；除息按原股息应收规则入账；适用规则要求初扣时按其实际阶段记已纳税及应收/现金；转让确定最终税负、仅差额入应付/退款；券商实际扣付结转应付与现金。未卖可能补税只预留购买力，不提前记成本。派息晚于转让不丢失已确定税负。

2015年101号文用股权登记日划适用范围，2012年85号的结算说明也区分登记、持有期与扣缴。固定例为登记2015-09-07和2015-09-09、均在09-10派息，取得日2013-01-01、转让交割日2015-09-14、各100元应税股息：前者适用旧制长期实际税负5元，后者新制0元；不能因同派息日或卖出日在新政策后，就都选新制。此例不是全历史税表。机器边界黄金例另用明确标识的工程区间检验左闭右开；真实切换日的法定适用端点须按有效通知/实施记录填入，不能将工程端点当成VERIFIED事实。历史2011—2026缺一段，A0相应税务不能认证。

FIFO税批次至少有`lot_id, acquisition_trade_id, acquisition_tax_date, original_qty, remaining_qty, economic_cost, corporate_parent_lot_id`。按`取得日期、实际成交次序、lot_id`排序。每笔卖出消耗数量q，从首批取min(q,lot剩余)，逐批形成`TaxLotDisposal`；数量之和必须等于实际卖股数。

每个已登记分红事件保留`entitlement_id, action_id, lot_id, record_date, tax_profile_id, selected_rule_id, rule_selection_date, selection_date_basis, eligible_qty, unresolved_tax_qty, gross_per_share, tax_base_per_share, withheld_paid`。消耗一批股票时，对该批所有尚有补税关系的分红事件同步消耗相同的适用数量，不能只处理最近一次分红；买入发生在某次登记之后的批次不补该次税。

最终应缴额按该slice的税基×适用税率，扣除已经实际纳税的对应份额，仅差額新增负债/退款应收。派息晚于卖出时，已确定税额和原分红应收关系继续保存；现金尚未收到也不能丢弃税基。未卖部分的预留采用**当前若全部依法转让的税额**，按自然时间逐日重新计算；仅限制购买力，不提前作为已发生税负影响NAV。税表要求预扣时按真实预扣另记，避免重复。

税额舍入优先按券商规定的ENTITLEMENT/LOT/ACCOUNT_DAY粒度聚合后到分；需要把聚合税额分摊至slice时按未取整理论额比例分配，先向下到分，剩余分按小数余数降序、再按slice_id分配。各slice相加严格等于实扣总额，不让遍历顺序决定税费。

送转后税批次用官方比例关联旧批。取整产生零碎权利时先按整个账户事件计算官方应得整数总数，再按条款分配批次；禁止每个lot单独四舍五入造成合计多股。股份来源的税务取得日、红股税基未知时输出TAX_UNKNOWN，真实股数仍入账。

## H05. 账户、行情与事件接口

### 5.1 QuoteSnapshot

必填`security_id, quote_time, received_time, last, best_bid/ask, tick, lower/upper_exchange_bound, reference_preclose, trading_status, basis_id, raw_flag, source_ref`。

买单必须有有效ask、卖单必须有有效bid；last有效并不能替代缺少对手盘。tick模式时效3秒、账户5秒是技术上限。分钟代理显式使用MINUTE_PROXY，不把59秒前上一分钟收盘冒充3秒tick。

对于持有但暂时无成交股票，`ValuationMark`另存price、basis、原时刻、NORMAL/PROVISIONAL/UNRELIABLE。估值可使用的价不自动可用于下单。

### 5.2 AccountView

```text
account_id, strategy_id, asof, observed_revision, capital_revision,
positions:{security_id:Position},
cash_book, nonorder_cash_restrictions, trade_payables, contingent_tax_reserve,
receivables, residuals, units, nav, hwm,
open_order_ids, order_states_complete,
reconciliation_status, limitation_reasons, run_state, retirement_triggered
```

`Position`的quantity来自已确认成交及公司行动；mature_quantity不含尚未上市/未成熟部分；broker_can_sell是券商净可卖；本地预留分别标已反映与未反映券商冻结。不得把规范free_sell再减一遍券商冻结。

`units、nav、hwm`及日终dd均用H01的ExactRatio，规范缓存须与精确资产投影相等；不能用*_display恢复。NAV字段是由资产算出的缓存，不能作为手工输入覆盖股数现金；导入券商`total_asset`仅用于全账户对账。ETF视图可以通过人工归属表生成，但不能省略自己的现金承诺、委托终态和实际资金变化。

### 5.3 批次、订单和成交

`Batch`：owner、普通/风险类型、固定计划ID、窗口、account_revision、资本修订、授权上限、SELL/BUY/RECONCILING阶段。

`Order`：ID、券商ID、side、数量、限价、首次提交时刻、尝试序号、累计量额、计提费用、终态、资源ID。原始数量及限价提交后不可直接改写；改价须撤销确认后发新单。

`Fill`：账户、交易日、市场、trade_id、order_id、证券、方向、成交时刻、收到时刻、数量、原价、金额、来源。独立trade_id相同价量不是重复；相同trade_id内容冲突不能吞掉。

每证券同方向只可一张未结单；同证券买卖在同批不交叉未结。若有旧买单且风险要卖，先取消买单并核对最终成交；新收到股数受真实T+1限制，不假设立即可卖。

订单转移唯一采用D09.3表，失效意图唯一采用D09.4；本节不定义另一套简化状态。Order另含`cancel_required, cancel_reason, cancel_request_id, last_control_revision, terminal_evidence, reconciled_filled_qty/value, applied_trade_keys`；终态证据保留来源版本/时刻/累计量额，不把它当Fill。BrokerEvent包括ACK、CANCEL_REQUEST、CANCEL_FAILED、TERMINAL、FILL；相同event_id同内容幂等，控制记录的新旧必须由已核验源版本确定，不能仅比较接收时刻。

末成交使累计达到原量时直接FILLED，包含从ACKED、SENT_UNKNOWN和CANCEL_PENDING到FILLED。终态累计大于已记逐笔时进入RECONCILE_REQUIRED并补齐，不重复记整个累计。冲突终态保留真实账和最大可能未成占用；f=q时未成占用为0但对账阻断可继续。未知不是永久CANCEL_PENDING的兜底。FORWARD_MANUAL仅生成动作清单与导入确认。

## H06. 规划与风险输出合同

### 6.1 WeeklyPlan

必填固定名单`buy_candidates_ordered`、持有模式、每股`target_amount`或锁股数量基础、E_decision、cutoff、execute_day/window、capital_revision、source_refs。名单顺序属于决策结果，不得执行时重排按明天可买性。

`TARGET_AMOUNT`与`HOLD_SHARES`不同：前者固定金额、当前解析差量；后者保持股数，仅公司行动调整基础。风控可覆盖两者。`EXIT`目标0。`HOLD_NO_ADD`正常不买、不因未知补选，确定风险仍可覆盖。

WeeklyPlan显式保留`score_status`和`ordinary_buy_allowed`。FLAT_SCORE批次buy_candidates_ordered为空、ordinary_buy_allowed=false；合格老仓截止权重>2.5%时可产生TARGET_AMOUNT及prohibit_buy=true；2.6%老仓向原2%金额减持，1.4%老仓不补。全局不健康仍按D05.4暂停普通调权，不与“数据健康但评分恒定”混为同一状态。

### 6.2 RiskDecision与FinalIntent

`RiskDecision`为同一account_revision/quote_revision上的只读裁决，包含`global_buy_blocks: [Reason]`、`security_buy_blocks: {security_id:[Reason]}`及活动目标。原因集合稳定排序后序列化；执行器必须先读取全局集合，再读取目标证券集合，不额外把SECURITY_EXIT升级成全局限制。FinalIntent中的prohibit_buy是该裁决与普通计划禁买的并集结果，不得另作不一致计算。

```text
security_id,
ordinary_mode, ordinary_amount_or_quantity,
max_remaining_shares_or_amount,
risk_episode_ids, priority, prohibit_buy,
valid_window, cap_reference_date,
reason_codes, account_revision, quote_basis, plan_id
```

这里只表达经济目标。`size_order`负责把它与当前quote、RuleBook、费用和真实现金变成合法Order；普通目标不可扩，卖量不超free_sell。任何重新解析都返回新account_revision，旧预览不能直接用来报单。

### 6.3 资源所有权

每个可用资源只可处于FREE、PREAPPROVED、BROKER_FROZEN、CONSUMED、RELEASED中的一个状态；状态变迁事件带同一个resource_id。容量、现金、股数、槽位是不同单位，分别计数；不使用一个金额字段代表所有限制。

真实证券槽=非零正常仓∪未结束新买证券。卖出部分未清不释放；确认没有股数且没有未结相关委托才移除。残余权益转出槽位必须有生命周期事件，仍占经济权益和风险。

## H07. 事件顺序、晚到记录与恢复

### 7.1 正常事件优先级

同一可见时刻先遵循来源已核验序号；无更细序号时：

1. 已有依据的除权/股份上市/可卖释放，使用此前锁定权益。
2. 该时刻之前已提交订单的成交与终态。
3. 实际现金到账、费用结算、明确资本转移。
4. 行情与其他事实更新。
5. 若处于日终，完成登记日权益快照（必须已经处理当日全部已确认成交），再计算日终NAV。
6. 风险状态/段更新、周度截止计划。
7. 本时刻的新授权、报单、撤单请求。
8. 提交事件序号与派生快照。

登记权益不是第1项的盘前事件；不能先锁登记股数，再处理已经发生的收盘成交。10:01先看到[10:00,10:01)中原订单的撮合结果，后发到期撤单请求；同一10:01新单不能消耗此前一分钟行情量。

### 7.2 一条已确认事件只改变账本一次

`apply_confirmed_event`依event_id检查：同ID同内容直接返回已经处理；同ID异内容RECONCILE_REQUIRED；新增事件先计算新股数/现金/税/资源，再一起校验并提交。券商实际已确认但超本地保护的成交仍入真实账，并新增违规原因。

事件尚未提交而进程崩溃，重启不能假定未向券商发送；SENT_UNKNOWN仍先查。日志提交不等于券商受理；两个事实分别记录。

### 7.3 晚到公司行动和历史修正

若只是晚收到成交且真实顺序可重建，以不可变的已确认成交为事实重建账户投影，不重新生成过去订单。若新增公司行动生效早于已经记账的交易，暂停新增，查清股份基础和成交数量，**使用全部实际成交与修正事件重新投影**；产生新的account_revision及调整记录，不制造虚拟买卖对平。

决策日志保留当时已知输入与已经发生的行为，不因为今日修复而声称昨日用了正确资料。会计重列净值与当时已报告净值分别标识；投研复验另run_id从最早影响事件前开始。错误数据造成停用只能按V5人工核正解除；真实风险触发不能因重列或重新入金抹去。

若股份/费用差异仍无法定解，保留原始事件与冲突，输出UNKNOWN，不凭“更接近券商余额”的方案修复。这里是一个账本的可重建投影，不是维护两套择优净值。

### 7.4 跨资本流重投影与精确快照

以下字段是不可变事实：实际资本金额F及occurred_at/known_at、已确认真实成交/费用、来源事件原文、当时决策输入与操作日志。以下为派生量：每次发行/注销份额、流前NAV、日终NAV/HWM/DD、当前余额投影和缓存。事件可保留`units_delta_observed`作为当时审计读数，但重建绝不把它当作实际资金流的替代输入。

固定链：初始1000份、100股×10元、E=1000；除息后股票900且应收100，但资料晚到，临时报告漏应收；此时真实转入900元，临时投影U=2000。补齐在转资前已生效的应收后，按事件经济顺序重建：转资前E=1000、U=1000、NAV=1；发行900份，最终现金900＋股票900＋应收100=1900，U=1900、NAV=1、HWM=1、DD=0。错误的1900/2000=0.95不是有效修正结果。

账户只保留一份当前有效投影；旧2000份及0.9临时净值作为历史报告/决策审计保留并标SUPERSEDED。不得把当时未知分红写成当时已知，也不得倒造订单。重列发现的历史风险变化进入V5既定的数据纠错/人工核正与投研独立重放流程，不执行回溯订单，不自动清除真实停用标记。

更正提交时增加projection_revision、标记最早受影响effective_at；早于该时点且数据版本适用的快照可作锚，之后快照一律失效重建。`ExactAccountSnapshot`仅是账户精确投影切片（完整账户仍按H05）；其detail_version、projection_revision、last_committed_seq、equity、units/nav/hwm/dd均须校验。不得使用旧快照中的派生份额跳过前面的资本流。崩溃后按同一纠正事件恢复，重复导入不再加100应收、不再加900资金；任一断点的最终精确结果均与全事件重建一致。

D1近似份额快照不设静默兼容分支；缺原始资本流或可信初始状态而不能精确恢复时，输出EXACT_STATE_REPLAY_REQUIRED。只由确定历史输入生成的新D2精确快照才可恢复执行。

## H08. 回放、黄金结果与采用输出

### 8.1 行情投递

历史引擎只向决策模块暴露`available_at <= engine_now`的事实。撮合模块可以读取正在结算区间的真实开高低收量以产生结果，但这些未来区间字段不能传回该区间起点的报价或因子对象。

日线使用09:30代理，仅允许代理之前的事实；分钟订单10:00首次对应[10:00,10:01)。日线报告无论多好都有NOT_WINDOW_CERTIFIED。引擎不能为完成订单自动从日线切分钟或反过来。

### 8.2 单元输出记录

```text
cell_key(role, capital, permission, package, start, scenario),
input_versions, execution_mode, start_cutoff, end_D,
startup_status, evidence_reasons,
retirement_triggered, trigger_at, retired_at,
ledger_path, event_path, plan_path,
CAGR_decimal, MDD_exact, worst_peak/trough/recovery,
healthy_week_count, assessed_week_count, unknown_week_count, longest_bad_streak,
fee_total/by_kind, turnover, stock_ratio, frozen_exit_ratio,
unfinished_orders, residual_rights,
qualification_reasons
```

所有格都产记录，即使未启动或数据不足。不存在只输出净值成功的格。金额、参数或权限改变产生不同cell_key。

### 8.3 资格判定总函数

先收集所有已确认硬失败，再收集决定性未知；有硬失败返回REJECTED并仍展示未知，有未知无硬失败返回INSUFFICIENT_EVIDENCE；测试包只能ENGINEERING_ONLY。只有满足全部16格硬条件，才计算八格稳健年化和与B0/ETF比较。

配置的语义身份由固定规则值、因子公式版本与参数、资金、权限、费用和执行配置的规范化内容确定，不以文件名、package_id或run_id代替。直接比较这些内容即可，无需全量哈希基础设施。重新申请时必须链接先前停用记录、列出实际变化或错误修复、完整复验及用户新决定；只是换名字的同内容配置仍被否决。

相同稳健年化的成本次序明确用四起点S0/S1中**最高年费用率**，而不是任挑手续费较低的一格。B1仅风险更好但收益较低的取舍需要用户裁决；不能新增“风险加权分数”自动宣布获胜。

## H09. 需要由开发者实现、无需另作投资判断的校验顺序

1. JSON结构与类型 → 版本/固定常量 → profile状态及scope → 日期区间唯一匹配。
2. 身份、单位、股份基础 → 源优先及冲突 → 历史可用性 → 经济池。
3. 包联合有效 → 精确排名 → 持仓/计数 → 普通固定计划。
4. 账户对账及单位净值 → 风险段 → 合并目标 → 费用后数量 → 双现金门/容量/槽。
5. 批次授权 → 预约 → 人工报单/模拟 → 成交与取消 → 单一账本 → 重新风险检查。
6. 日终记录与覆盖统计 → 四起点四情景完整矩阵 → 先资格后收益 → 人工采用。

解析错误不运行；来源未知不默认为正常；业务阻断不抛成不可诊断的异常；已确认的真实交易违规照实入账并停止新增。

## H10. 开发边界

JSON Schema是输入结构约束，不替代V5经济条件、外部来源核验或测试用例。模板中的UNKNOWN/null应当使相关功能返回清楚的阻断，不应妨碍纯数值、账户与回放骨架的合成开发。接入真实输入时只补事实，不重新选择主算法。

本版不提供真实API凭据、账户ID、已批准因子或完整法定历史表。实现者不得把测试Profile复制成真实Profile，也不得把本轮数学oracle当作可用于实盘的账户模块。


## H11. Schema覆盖边界

`bundle.schema.json`校验外部Bundle；其中新增的ExactRatio、ExactAccountSnapshot、DividendEntitlementBinding定义同时由`inputs/runtime_contracts.schema.json`引用，供精确切片/税绑定交换与恢复检查使用。这不是完整生产账户状态Schema，也不把文档对象一律开放成任意JSON。`normalize_study`及Profile引用、Rat规范约分、缓存重算、税区间唯一匹配、订单累计一致性均是必做业务校验；结构通过不能代替这些检查。两份模板仍标TEST_ONLY/NOT_PROVIDED，不补造真实税表或账户能力。

非日终精确状态切片允许当前NAV高于上一正式日终HWM；dd缓存保持`1−NAV/HWM`的有符号精确值。该切片不是新增的日内回撤触发器；正式日终按D12先更新HWM，再形成评价DD。

## 1. 本包范围和结论

## 3. 本轮关键修订的数值及语义落点

### 3.1 禁买范围

`RiskDecision`唯一输出全局与证券级集合。2%个股退出受阻、无其他全局问题且普通退出已确认时，可形成无关固定名单买单；五只各2%受阻达到10%时关闭；2%受阻但另有总暴露纠偏也关闭。执行器不能以“还有任一风险段”为第三套裁决。

### 3.2 精确净值门槛

初始权益75000、份额100000、高水位1，实际转入1元：新份额为300004/3，权益75001，NAV恰为3/4，DD恰为1/4，正式日终触发25%。原50位Decimal算法确实得到略高于0.75的NAV并漏触发；提高精度或epsilon都不是本版修复。

金额实结的取整规则不变。份额、NAV、HWM、DD和硬比例比较用规范化任意精度有理数；序列化和恢复使用整数分子/分母字符串。旧近似份额快照不能直接转有理数冒充精确，必须从原资本流、权益事实和基线重建，资料不足则阻断恢复。

### 3.3 订单终态及取消竞态

固定买单300股、限价10、现金10000，先成交100，再请求撤销，确认前再成交200：最终300股、现金6995、总佣金5、未成预约0、已用容量3000；不留在CANCEL_PENDING，不自动补报。

参考链也覆盖自然满足的风险卖单、资本修订后的旧买单、成交先于ACK、撤单失败、待补逐笔终态、相容迟到与不能判旧的冲突记录，以及中断恢复。可信真实成交总是入账一次；未知不变成确认撤销；全成后不继续保留不存在的未成数量。费用结算可能晚于订单终态，相关负债另计。

### 3.4 税则选择与晚到会计修正

本税类固定以股权登记日选择税制；取得日与转让交割日决定持有期，计提和实扣又分别由清算规则决定。2015年两个登记日样例及2020年纯工程边界样例分开，不用工程日期填补真实历史税表。

迟到应收样例：100股除息后值900，应收100实际已生效；其后实际转入900。更正投影必须重算资本流派生份额为1900，最终权益1900、NAV1，而不是保留临时2000份得到0.95。实际资金流、真实交易和当时决策日志保持原样，不倒造订单，不让会计重列假装当时已知。

### 3.5 FLAT_SCORE的明确解释

V5禁止恒定评分时新增和排名替换，没有要求一并取消不依赖排名的普通减持。本版选择：合格老仓超过2.5%可向2%减持；低于1.5%不补买；不得因执行时价格变化把原减持反向变成买入。这是对V5未完全展开部分的显式解释，并改变D1“全部普通调权暂停”的行为，不伪称纯文字修复。

## 4. 剩余外部输入与精确施工边界

## 2. 业务语义是否改变

**V5策略参数及架构方向未变。** 数据来源政策、证券互斥、共享现金、400池、30/45、60%/65%、单股/行业限额、20%/25%/30%、四起点四情景及停用否决均保持。

相对D1的实际程序行为会发生必要变化：不再因2%个股退出受阻禁买所有股票；精确等号正确触发；失效订单得到明确取消；税制按登记日绑定；恒定评分下允许符合条件的普通减持。这些变化已经写入规范和测试，不应继续用D1相反行为作验收标准。

其中FLAT_SCORE是对V5未完全规定的细分行为作显式解释，采取“不买、不按排名换股、保留普通减持”的确定方案。其余主要是合同冲突修复、数值精确化及已有规则的事件链补齐。没有增加因子搜索、仓位优化、自动恢复或真实撤单功能。

## 3. 接口与恢复的版本边界

本包只接受V5D2 Bundle、标准REPLAY枚举及规范ExactRatio。不是给D1增加宽松兼容层。金额字符串不变，精确排名/净值类对象改为分子分母整数字符串；旧浮点或已舍入份额不自动转换成“精确历史”。

历史D1运行如需接续，必须从可信不可变事件重建派生份额与净值。若原始数据不足，返回EXACT_STATE_REPLAY_REQUIRED。新项目从确定的初始事件启动，不受旧快照缺口阻碍。晚到更正同样保留事实和当时决策审计，只重建派生状态，不倒造或删除实际成交。

## 4. 进入开发的判断与剩余阻断

**本轮所列设计冲突已给出唯一规则，并同步到文档、Schema、模板、黄金向量和局部校核；可以开始按V5D2编码。** 这是一项限定于已审范围的设计可施工判断，不是证明全部未来代码不存在缺陷。

当前没有必须让开发者重新选择的投资规则或接口格式。实现必须补齐G01—G19对应的生产测试；关键失败没有通过时不能宣称编码完成。96格历史回放、QMT/券商和共享现金外部验证仍未运行。

实际因子定义、资金/权限、券商清算税表和数据/账户能力仍是概要V5允许待补的外部事实。其缺失不阻挡使用TEST_ONLY输入开发通用骨架，但会阻挡对应的真实启动、采用或共享实盘。不能将外部未知填成VERIFIED，也不能为了“直接开发”删除必要阻断。

## 5. 如何使用本包复验

先运行`verification/verify_design.py`和`verification/verify_revision.py`，再运行`verification/check_documents.py`。前两者是局部参考检查，第三个是文档/输入一致性检查。各自实际结果单列，不相加成独立业务覆盖。

开发者从自己的订单、风险、账户和导入入口执行G19固定事件，不能仅调用附带oracle获得同一输出。所有黄金预期事先保存在JSON中；新用例没有将未运行的生产清单改成PASS。
